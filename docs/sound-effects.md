# Sound effects

Open **Media → Sound effects**, search by name, tag or creator, and choose a category. Expand a row’s tags to inspect its action, material and style keywords; click a tag to search it. Preview a row with its Play button; the volume control changes preview loudness only. Adding a sound opens the ordinary Media import result. Drag that imported asset onto an audio track to use it in an edit. Imports do not automatically place clips or change their gain.

See the [desktop](images/sound-effects-library.png) and [narrow-screen](images/sound-effects-library-mobile.png) library views.

The collection contains **1,039 distinct sounds across nine categories**, prepared from 11 CC0 source collections. All 281 initial sounds remain available; this expansion adds 758 effects. Files are served with LocalCut and fetched only when requested. No account, external sound service or API key is needed. CC0 does not require credits in a finished video; each row still links to its source. The complete [source lock](../scripts/sound-library.lock.json), [catalogue](../public/sounds/catalog.json), [measurements](../public/sounds/measurements.json) and [third-party notices](../THIRD_PARTY_NOTICES.md#bundled-sound-effects) retain provenance.

## Catalogue and interaction contract

The Media action loads its dialog and catalogue on demand. Opening, searching and previewing do not create a project or import audio. One preview plays at a time. Volume changes made during a download apply when playback starts. Changing the search, category or page stops it. Closing, navigating to another project/route or entering a historical read-only view retires the dialog, stops playback, revokes its object URL and aborts unpublished downloads. Historical views expose no sound-library import action.

The catalogue's schema, category list and search live in `src/core/sound-library.ts`. The workspace loader validates that schema and verifies each requested file's byte count and SHA-256 before preview or import. A mismatch makes one HTTP revalidation attempt, then offers an actionable failure. Only checksum-derived local audio paths are constructed; creator links must use HTTPS. A failed catalogue can be retried. Failed sound requests can be retried through the same row.

The dialog retains at most one prepared file for preview/import reuse. Imported originals, deduplication, folder placement, job progress, project identity and retention stay with the existing shared media importer/editor. Once submitted, those durable jobs keep their existing completion semantics. A late download cannot import into a newly viewed project. Imports from a folder target the folder captured when opening the sound browser; imports from Trash target the Media root. No project schema, public editor API or derived-computation cache is added. External tools use the same catalogue/file loader and existing engine import/placement owner.

This is a bundled collection, not a service-worker offline feature. Loading the app/catalogue or a previously unfetched sound still requires the hosting origin; see [browser and offline limits](browser-support.md#storage-backups-and-offline-use). After import, sounds are ordinary local assets and can be included in backups with originals.

## Agent search and import

`localcut_catalog` with `kind: "sounds"` searches names, categories, tags and creator/source names. Keywords are case/accent insensitive and AND-matched; whitespace and hyphens separate words. Use action/material/style terms rather than an entire sentence, for example `paper page turn`, `pavement walking`, `cards shuffle`, `retro victory` or `river stream`. Results retain deterministic catalogue order. They include complete tags, integer durationUs, category, format/size/hash, CC0 licence and original creator/source URL.

Optional category, exact tags (all must match) and minDurationUs/maxDurationUs narrow results. Default limit is 50, maximum 100; offset/nextOffset page the complete match set. Facets count matching categories and the 100 most frequent matching tags. An empty query returns the collection; an empty result means no match within the supplied filters, not an empty project. Discovery fetches metadata only.

```json
{
  "kind": "sounds",
  "query": "laser",
  "tags": ["retro"],
  "maxDurationUs": 1000000,
  "limit": 10
}
```

Pass a chosen item.id as soundId to `localcut_import_media` with the inspected projectId and optional parentId. Supply either soundId or the existing name/mimeType/base64 file fields; mixed inputs and sound relinks are rejected. The tool fetches and verifies bundled bytes, rechecks the viewed project/read-only/busy state, then returns the ordinary engine import job. Wait with `localcut_job`; its result provides the asset and library revision. Add clips separately with revision-aware `localcut_apply_edits`. Inspect Media before retrying a lost import response. No arbitrary URL is accepted.

Cancellation, route retirement or a changed view prevents unpublished downloads from starting an import. Already committed originals finish placement in the captured project/folder under existing engine publication rules. The portable [audio-editing skill](../public/skills/localcut-audio-editing/SKILL.md) contains this workflow and a UI fallback; see [WebMCP](webmcp.md).

Every sound has 4–19 lowercase, unique tags, with 447 distinct tags in this snapshot. The vocabulary uses creator labels, archive families, materials, actions and straightforward use synonyms: book/page/paper/turn, concrete/stone/pavement/walking, coin/money/reward, confirmation/success/notification, laser/zap/blaster/space, and retro/8bit/arcade/chiptune. Full provenance stays separate from search tags. Tags are editorial metadata, not an embedding model or a listening-based semantic certification. `retro human death` is a synthetic game cue, not a real human recording; loop candidates are not certified seamless after preparation. Actual duration filtering uses measured metadata rather than a descriptive short/long tag.

## Research and source decisions — 13 November 2026

The research compared original pack pages, included licence files, publisher restrictions and individual recording descriptions. Searches covered CC0 creators, stock libraries, field recordings, transition effects and library classification. This is a bounded source and implementation review, not an exhaustive survey or independent legal clearance of every contributor's ownership. Selection criteria were permission to redistribute reusable files, traceable acquisition, useful editing coverage, native decoding and a practical static-download size.

### Organization and sound treatment

The reviewed snapshot provides 111 transitions, 247 interface sounds, 222 impacts, 76 footsteps, 95 Foley sounds, 117 digital effects, 166 sci-fi sounds, two room tones and three nature excerpts. These are broad editor-facing groups, with searchable material/action synonyms. The [Universal Category System](https://universalcategorysystem.com/) informed the value of consistent source/category naming; this small catalogue does not claim full UCS classification or compliance.

All outputs are 48 kHz, 16-bit PCM WAV, retaining mono/stereo channel counts. Kenney's compressed Ogg originals remain identified in the lock; WAV conversion improves import consistency, not the fidelity of the original recording. The recipe resamples, reduces gain only where necessary to keep sample peaks at or below −1 dBFS, then quantizes to 16-bit PCM. Quiet sources are not boosted, and no blanket LUFS normalization, denoising, compression, spatial widening or pitch changes are applied. Different effects still need scene-specific mix levels.

Sources longer than 20 seconds become explicit first-20-second excerpts with 20 ms edge fades. Short effects keep their full source duration and existing attack/tail. No source is certified as a seamless loop. Measured output sample peaks range from −28.37775 to −1.00015 dBFS; these are sample peaks, not true-peak or broadcast-loudness measurements. The audio total is 100,632,462 bytes (96.0 MiB), with a checked 112 MiB ceiling. The expanded size replaces the initial 60 MiB budget to cover the requested larger collection; all audio remains outside the eager JavaScript graph and is requested per sound.

Every candidate was decoded and measured by the recorded FFmpeg toolchain. The preparation rejects missing, non-finite, silent or unsupported-channel output. Build checks inspect every actual PCM WAV, source selection, notice, checksum, duration and size in both hosting outputs. Measurements do not establish subjective quality, clean natural transients, mono compatibility or the absence of upstream recording damage. This delivery does not include a subjective listening review; native browser playback and editing acceptance are separate evidence.

### Coverage limits

This collection emphasizes practical short cues, retro/sci-fi effects and reusable creator packs. The 512 retro variations increase choice within families rather than representing 512 new real-world subjects. It has limited real-world ambience, cinematic sound design, crowd/vehicle/animal coverage and no recorded dialogue/voice library. Those gaps should be filled from individually reviewed original recordings or commissioned material, without relabelling restricted stock as CC0. Expanding attribution-based sources would also require a clear credit workflow for exported projects.

## Reproduce and verify

Use the [source lock](../scripts/sound-library.lock.json) to acquire its exact originals into an ignored local folder. Kenney downloads use the creator's normal pack download; the lock stores the stable page rather than an expiring signed URL. For archives, retain the archive filename and checksum. The preparation performs no network access and refuses mismatched originals, members or recipe/tool versions.

```sh
python3 scripts/prepare-sounds.py --sources .cache/sound-originals --output .cache/sounds-rebuilt
node scripts/check-sounds.mjs .cache/sounds-rebuilt
```

Use the recorded FFmpeg version for byte-for-byte output. Compare file hashes and parsed catalogue content with `public/sounds/`; JSON whitespace is presentation only. Do not overwrite the shipped collection with an unreviewed rebuild. New sounds require refreshed rights review, the lock/recipe hash, notices, measurements, the generated catalogue/WAVs and affected documentation together.

```sh
pnpm test tests/unit/sound-library.test.ts tests/unit/sound-library-tools.test.ts tests/unit/webmcp.test.ts tests/unit/media-import.test.ts
node --test tests/tooling/build-state.test.mjs
pnpm test:ui --grep 'sound library|agent sound'
```

The last command verifies/reuses both production builds and runs the focused native Chrome journeys. Builds validate source assets without external downloads; bundle checks validate packaged files at `/` and `/LocalCut/`. Source, lock and preparation/checker changes invalidate verified-build reuse. See [development gates](development.md#expand-verification-at-the-boundary) for the remaining static and draft handoff requirements.
