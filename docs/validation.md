Use the [development guide](development.md) to choose focused checks while editing. This document defines the broader local acceptance gates; a focused pass does not replace the applicable handoff checks.

Validation runs locally. `pnpm check` covers formatting/lint/type checking, unit tests, production builds/artifact budgets, and Chrome integration; real transcription/cached replay and performance have separate local commands. Native codec support is required; missing AAC/H.264/VP9/Opus fails the gate. Browser tests use installed stable Google Chrome, never a generic Chromium-only substitute. `LOCALCUT_CHROME_EXECUTABLE` can select an installed Chrome executable; otherwise the configured Chrome channel is used.

Hosted CI is disabled. Earlier hosted results remain historical evidence for their recorded revisions, not a current handoff requirement. GitHub Pages builds and publishes automatically on pushes to `main` under the user's explicit preference; this release workflow does not run hosted validation.

Tests serve the real production outputs at / and /LocalCut/. Workspace tests use the production interface; headless engine tests create their own presentation surfaces. Test harnesses and fixtures are absent from deployed assets. Generated PNG/WAV fixtures exercise known colors, transforms, timing, tone frequency, and waveform behavior. The attributed JFK speech fixture checks actual local inference.

The default `chrome` project runs normal acceptance tests with resource-aware concurrency, up to four workers. CPU affinity, current load, available memory/reclaimable cache and cgroup CPU/memory quotas constrain one shared budget. The main `check` overlaps independent static gates and units/build preparation within that budget; both builds stay sequential and browser consumers wait for bundle validation. `LOCALCUT_TEST_SLOTS` (1–8), `LOCALCUT_UNIT_WORKERS` (1–8), and `LOCALCUT_BROWSER_WORKERS` (1–4) provide bounded overrides capped by available capacity. A single slot gives serial processing. The opt-in `acceptance` project and live-provider configuration remain serial. Transcription/performance are explicit separate gates.

`pnpm test:safari` adds native Safari on macOS through Apple’s installed `safaridriver`. Enable Allow remote automation in Safari’s Develop → Developer Settings before first use. The serial suite allocates separate loopback driver/server ports, verifies both static builds, and creates and deletes only `test-safari-*` namespaces. At both base paths it encodes/reimports image + stereo WAV, reimported AAC, and silent MP4 output; asserts H.264/AAC metadata, frame colors, duration, 48 kHz stereo, RMS signal/silence and tone onset within 50 ms; then reloads a committed revision. Missing capabilities or automation prerequisites fail. Results (including Safari capabilities) and failure screenshots are retained in `test-results/safari/`. This focused native suite does not establish full Safari, WebM, inference or performance parity; complete Chrome gates remain required.

For faster workspace iteration, `pnpm test:ui` runs all workspace specs against both production base paths. Additional Playwright arguments work normally, for example `pnpm test:ui --grep 'speed rounding'`. Before running, it checks SHA-256 fingerprints of source/public files, build configuration, lockfile, build scripts, relevant build environment, and every generated file. Source-directory `AGENTS.md` files are instruction metadata and are excluded; other source files remain tracked. Stamps are stored only in ignored `.cache/build-state/`. Changes to documentation or tests reuse current assets; changed inputs or missing/modified output rebuild the affected target. This focused command supplements `pnpm check`, whose build identities and full normal Chrome gates are always verified. Use `LOCALCUT_TEST_PORT` to select a port when another test server is running; do not mutate shared build directories during browser tests.

The final 39-test normal browser suite passed with both worker settings on the same local Chrome 155.0.8059.40 installation: 62.86 seconds with one worker and 33.0 seconds with two, a 47.5% reduction in this comparison. Neither run skipped or retried tests. An isolated build-cache probe exercised 32 invalidation/reuse assertions, including source/config/dependency/environment changes, missing/modified output, separate base targets and corrupt stamps. A real focused speed-rounding run reused both production builds without rebuilding. These are local observations, not a guarantee for every machine.

Playback recovery acceptance observes native timeline progress with a five-second deadline, then verifies pause stability and exact seeking. It does not assume that a 150 ms wall-clock sleep equals a fixed amount of audio progress on a busy runner. Failure output includes the actual observed microsecond position; the test still fails if playback stalls or only completes without observable intermediate progress.

Domain tests cover validation, atomic pure rollback, editing operations, stable nested IDs, partial updates that preserve omitted fields, split keyframes, rational timing, subtitles, fades, source caption mapping, and anti-alias resampling. Controlled storage tests cover import completion during recovery scans, cancellation or rejection of queued shared leases, and cancellation on both sides of the transaction commit. Dependency tests exercise prohibited static and dynamic imports across the pure-core boundary. Chrome integration checks storage commits/receipts/history, atomic rejection of missing or foreign-source transcripts and legacy imports, two-tab conflicts, both real export formats reopened and decoded, empty-MIME image imports, compositor transitions over lower tracks, crops/rotation/effect order, resolution-scaled blur, waveform/proxy/contact sheets, audio speed and onset, stereo overlap/gain/fades/block continuity, recovery, missing media, cancellation, inert initial workspace, and owned storage. Native worker result races verify that cancelled exports leave no file and undelivered frame bitmaps are closed.

Upgrade regressions use a committed fixture generated by the actual `984107d` Store, commands, and parser modules, with source hashes recorded in the fixture. Production Chrome seeds its old project/history/receipt records directly into IndexedDB. It verifies old successful requests replay after parser changes, changed or newly supplied content conflicts, and new raw request fingerprints survive reload. Two actual tabs concurrently open the same unmarked project and agree on the atomic migration. Undo/redo after track reordering retain cue ownership; backup round trips retain normalized IDs. Default legacy imports and marked corrupt backups remain strict, while the explicit legacy repair option accepts only the supported unmarked cue-duplication case.

Transcription acceptance prepares the real model, checks the expected phrase and ordered segment timestamps across an overlapping window boundary, cancels active inference without saving a transcript, and restarts with automatic language detection. A source interval whose endpoints are not aligned to 16 kHz samples checks exact persisted cue bounds and project backup linkage. It disposes/reloads, blocks every remote host, and invokes a fresh inference worker against persisted caches. Cache clearing must retain the transcript. Read-only remote download methods are checked.

LOCALCUT_ASR_CACHE=.cache/asr-5332fcc35e32a33b86612b9a57a89be7906102b1 pnpm test:transcription

The test verifies each cached file again before serving its pinned download URL to the real browser preparation flow. Inference uses the actual model/runtime, and the reload replay blocks remote hosts. Without LOCALCUT_ASR_CACHE, the same test downloads from the remote pinned URLs and depends on their availability.

The manual performance gate first encodes and reimports a one-second H.264/AAC source with an animated gradient and distinct stereo tones. It repeats that real video/audio source under animated text, warms up, exports two and five minutes at 1080p30, reopens media, checks duration and interactive seeking during export, and measures browser/worker native RSS via CDP process IDs and ps. The steady-state five-minute RSS delta must stay below 128 MiB versus two minutes; processing must not retain full-project frames/audio. Attach raw measurements and hardware/browser versions when publishing evidence. This test is a bounded generated workload, not a claim about arbitrary media complexity.

The performance test uses a fresh temporary disk-backed Chrome profile and removes it after closing the browser, including on failure. [Playwright's default contexts](https://playwright.dev/docs/browser-contexts) are incognito-like; [Chromium uses an in-memory filesystem delegate for incognito storage](https://chromium.googlesource.com/chromium/src/+/main/storage/browser/file_system/obfuscated_file_util.cc). A write-only 100 MiB probe grew browser RSS by 103.2 MiB in the default context and 5.8 MiB in the disk-backed context. The original memory failure counted the output file itself as RAM. The retained test measures the same complete browser/worker RSS and keeps the 128 MiB gate unchanged. Per-process RSS is attached to distinguish browser storage from renderer processing. The custom profile fixture retains a trace on failure.
