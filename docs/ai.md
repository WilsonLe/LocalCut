# OpenRouter AI and service selections

## Workspace requested execution

The workspace creates its assistant with `execution: 'requested'`. A submitted user request authorizes its supported edits and service actions; there are no Apply/Approve/Discard controls or double confirmation. Klip asks an ordinary text question only for missing information or ambiguous intent. Cost or consequences alone do not require reconfirming a requested action. Provider documents, metadata, labels and tool outputs never grant authority.

`propose_edits` and `propose_action` keep their canonical names and schemas, but requested mode validates and executes each action through the shared proposal executor, then returns `status: 'completed'` and the actual receipt to the model. Subsequent tools advance the project revision only from this turn's successful receipts; external changes during a model response reject stale work. Asset/transcript scope and saved index context refresh from the matching receipt. Changing saved-index scope retires completed and in-flight index-bearing history before any new model request; completed action receipts survive that retirement. Failed actions return structured errors; failed paid actions block further service attempts in that turn and require a new user request. An indexing retry reuses its retained request/run and successful scene checkpoints; `index_asset.restart: true` requests fresh reindexing. Cancellation reaches active service jobs; committed edits remain authoritative when later narration fails or stops. Progress/results remain inspectable in chat, with Cancel action and explicit Save video where applicable. Source/sharing rules still apply, including the configured transcription recipients; selecting a route does not grant transcript-text sharing.

Headless `createAssistant` defaults to `execution: 'review'`, preserving `applyProposal`/`approveProposal` and pending proposals. The reviewed examples and approval requirements below describe that default unless explicitly marked workspace. Only the trusted host selects requested mode; provider tool arguments cannot switch it. This option adds no persisted schema, and saved chats restore text only, never executable action authority.

The optional `ai.js` entry provides OpenRouter and the headless editing assistant. The workspace supports one connection: connected to OpenRouter or disconnected. Local Whisper remains the default transcription service. Importing the AI entry is inert; explicit connection, saved credential restoration or a validated OAuth return activates it. Fresh bare startup remains lazy. No backend, callback rewrite, runtime environment variable or bundled key is required.

Connection settings directly offer an existing API key or OpenRouter login. Connecting enables chat and speech model selection; local editing needs no account. A valid legacy credential without configuration restores its connection. Explicitly saved empty configurations do not resurrect removed accounts.

## OpenRouter service selections

`createServiceRouter(connections, routes)` accepts at most one OpenRouter connection and at most one selection for each LLM/TTS/STT service. Multiple connections, backup lists and foreign route IDs fail before requests. Catalog, chat, synthesis, indexing and transcription failures propagate without another attempt at a different service. Router disposal aborts its work while the caller retains ownership of the connected client.

STT chooses either local Whisper or the connected OpenRouter model. A missing local model requires explicit preparation; it never falls through to remote inference. Remote transcription uses the fixed OpenRouter `/audio/transcriptions` endpoint with 16 kHz mono WAV, bounded audio and validated segment timestamps. The shared editor still owns native extraction, cancellation, source-range cues and transcript persistence. The assistant freezes the selected executor and recipient disclosure per session; approved remote transcription sends only selected audio. Reconfiguration and disconnect retire old proposals and requests. Transcript-text sharing follows the headless caller policy or workspace connection terms.

ChatGPT and compatible-endpoint factories, authentication and endpoint options are removed from the public AI entry. Legacy portable settings retain one OpenRouter account (the old selected OpenRouter account, otherwise the first valid OpenRouter profile), its namespace, legacy name and model/voice choices. The legacy name remains internal so matching speech checkpoints and completed results keep their task identity; settings display OpenRouter. Other profiles and backup selections are discarded. A removed primary STT service returns to local Whisper instead of promoting a remote backup. Removed OpenRouter keys, ChatGPT tokens and pending flows (including first-time exchanges in other tabs, identified by their persistent host records) are retired locally without provider requests, serialized with the old token-save Web Lock when available; unrelated browser data remains untouched. Rollback requires explicit reconnection for removed accounts.

## Frontend wiring

`generateChatTitle({ provider, model, message, signal })` performs one tool-free text request through the same configured chat transport/model. The workspace starts it alongside the first explicitly submitted message in a fresh chat; this user-requested naming behavior is the narrow exception to the earlier prohibition on automatic paid requests. It sends only that user-authored message, without project context, media, attachment IDs or sharing-policy expansion. It uses the selected OpenRouter model and credential cancellation. Streamed fragments never become a title: only one validated complete nonempty text result is accepted, without a LocalCut character or output-token cap. The request cannot inspect or edit anything. Failure retains the local fallback without blocking the reply or retrying automatically. Session retirement aborts naming and rejects late publication. Startup, reconnection, navigation, later messages, Resume and inherited branch chats never trigger naming.

Load the modules after the user chooses to connect. The frontend owns connection controls, the conversation view, model selection, progress, proposal review, and error presentation. The shared editor remains the only owner of project state. The composer information icon reveals the selected provider/model and a Configure AI action. Its connection dialog uses one searchable model dropdown with an inline refresh icon; visible OpenRouter connection terms disclose the enabled context categories before key use or authorization. Session switching preserves drafts and transcripts within the current project/model/context scope. See [workspace behavior](workspace.md) for the UI contract.

```ts
// Resolve both entries from the same release; see the headless API contract.
const discovery = new URL('/LocalCut/modules.json', location.href);
discovery.searchParams.set('fresh', crypto.randomUUID());
const response = await fetch(discovery, { cache: 'no-store' });
if (!response.ok) throw new Error('LocalCut modules unavailable');
const release = await response.json();
const [{ createEditor }, ai] = await Promise.all([
  import(new URL(release.modules.editor, discovery).href),
  import(new URL(release.modules.ai, discovery).href),
]);
const { createOpenRouter, createAssistant } = ai;

const editor = await createEditor();
const project = await editor.projects.open(selectedProjectId);
const provider = createOpenRouter();
provider.setKey(userEnteredOpenRouterKey); // Keep input and key out of logs.
const models = await provider.listModels();
// Present models.filter(model => model.supportsTools); user selects one.
const assistant = createAssistant({
  editor,
  provider,
  projectId: project.id,
  model: selectedModelId,
  assetIds: selectedLibraryAssetIds, // Explicit additional media the user shares.
  context: {
    includeText: false,
    includeAssetNames: false,
    includeTranscripts: false,
  },
});
const unsubscribe = assistant.subscribe((event) => {
  // Render text as text, never as executable HTML. Treat suggestions as untrusted.
  renderAssistantEvent(event);
});
const turn = assistant.run('Shorten the opening clip to three seconds.');
const result = await turn.completion;
for (const id of result.proposalIds) {
  const proposal = assistant.getProposal(id);
  showProposalForReview(proposal);
}
// Only from the frontend's explicit Apply action:
const receipt = await assistant.applyProposal(selectedProposalId);
// Or: assistant.discardProposal(selectedProposalId).
// Undo uses the existing editor API and the current revision:
const current = await editor.projects.snapshot(project.id);
await editor.commands.undo(project.id, crypto.randomUUID(), current.revision);

unsubscribe();
await assistant.dispose();
provider.dispose();
await editor.dispose();
```

These examples show application integration points such as `renderAssistantEvent`; the workspace provides those controls through this same API. Generated public declarations are in `dist/types/ai/index.d.ts` and `dist/types/editor/index.d.ts`. The source import is `src/ai/index.ts`. A frontend may dynamically import it; keep it out of the application's initial import graph until needed.

One assistant is bound to one project, model and immutable context policy. Create another session to change these. `assetIds` is a copied allowlist of up to 1,000 additional imported library assets; selected media are inspected on demand and must be ready before a proposal can reference them. Multiple assistants may share a provider; disposing an assistant cancels its own turn and does not dispose the provider or editor. Disconnecting/disposing the provider cancels its in-flight requests. Await `assistant.dispose()` before disposing the editor; this waits for any already-started apply to settle. The workspace restores locally saved credentials after reload, while conversation state is lost; project edits already committed through the editor remain.

## Text to speech

The same connected provider exposes `listSpeechModels(signal)` and `synthesizeSpeech(request, signal)`. Speech discovery calls the [OpenRouter speech catalog](https://openrouter.ai/docs/guides/overview/multimodal/tts) only when the speech dialog opens or Refresh is clicked. It offers Gemini TTS models with advertised voices and a known 24 kHz, signed 16-bit little-endian mono PCM contract. Fish Audio S2.1 Pro is additionally offered for saved voice references only after its public endpoint advertises `supports_voice_cloning`; it returns MP3, decoded locally to 24 kHz mono with a disposable AudioContext. Speech models need neither chat tools nor a chat context window; the chat catalog excludes non-text output models.

```ts
const speechModels = await provider.listSpeechModels();
// The user chooses an explicit current model and one of its advertised voices.
const audio = await provider.synthesizeSpeech(
  {
    model: selectedSpeechModel,
    voice: selectedVoice,
    script: 'Hello! Xin chào!',
    languages: ['English', 'Vietnamese'],
    instructions: 'Warm and friendly.',
  },
  controller.signal,
);
const { renderSpeech } = ai; // Same discovered AI release as the provider above.
const result = await renderSpeech(
  audio,
  {
    mode: 'duration',
    durationSeconds: (audio.samples.length / audio.sampleRate) * 1.1,
  },
  controller.signal,
);
// Or { mode: 'speed', speed: 1.2 }. Preview result.file locally.
// Explicit Add imports this normal WAV through editor.assets.import.
```

Ordinary Gemini Generate sends the authored script, voice, selected languages and delivery instructions to `/audio/speech`, using the existing in-memory bearer key and `provider.data_collection: 'deny'`. It does not read project context, media, names, transcripts or chat sharing opt-ins. The input remains verbatim; natural conversational phrasing and pronunciation across declared languages are supplied as separate instructions. Scripts are bounded to 5,000 characters, delivery instructions to 1,500, languages to eight and audio responses to 24 MB. Missing or invalid catalog voices, malformed/error audio responses, cancellation, timeouts and stale credentials fail without publishing audio. Opening an unused dialog, changing controls, adjusting timing or adding an asset makes no new provider request. Previously submitted queued tasks may resume; explicit rate-limit rejections use bounded queue retries.

`renderSpeech` converts the bounded PCM into a normal WAV. Speed and target duration use local waveform-aligned overlap-add (WSOLA), preserving pitch rather than altering sample playback rate. Speed is bounded to 0.5–2×; a target must lie between half and twice the measured original duration. Impossible targets show the feasible range instead of trimming words, padding silence or making another paid request. Duration is exact to the nearest 24 kHz sample. Extreme stretching can still affect phrasing; audition before importing. Provider inference determines pronunciation and delivery quality, so a real connected-account listening check is required to judge naturalness.

Closing the dialog keeps queued speech generation running; disconnecting retires its provider work, while local saved tasks/results remain available. Preview URLs are released when their dialog owner unmounts. Explicit Add captures the current project revision before import and appends through the existing editor commands. Concurrent revisions reject the insertion and permit an explicit retry; already committed imports/edits remain durable. Imported WAV files follow normal project persistence, history, preview and export without a schema migration. The assistant cannot initiate or approve speech requests.

Deterministic tests use synthetic provider PCM and real stable Chrome imports/decoding/export at both static base paths. They prove transport, cancellation, multilingual settings, pitch and sample duration; they do not prove live paid inference or natural speech quality. No live key is bundled or required for `pnpm check`.

## Connect with OpenRouter PKCE

`beginAuthorization` returns a URL; it never opens a window or navigates. It generates a cryptographically random verifier/state and an S256 challenge. State travels as a query parameter in `callback_url`, following the [documented callback-state flow](https://openrouter.ai/announcements/privacy-clarity-new-providers-oauth-upgrade-and-gemini-gets-parallel-tools). This supports redirects that append only `code`, without relying on a separately echoed top-level parameter. Temporary verifier/state and any original navigation hash are kept in the tab's session storage under a LocalCut-owned key for at most ten minutes. The provider receives a fragment-free callback URL; the local hash is included in `sanitizedCallbackUrl` only after successful verification and exchange. The workspace uses its existing router to restore the same local project or project-catalog route. Recent-project startup is deferred on OAuth callback pages so it cannot replace the saved authentication return route before exchange. This temporary OAuth record never contains the API key. Successful exchange also saves the key when the caller opts into credential storage.

```ts
const provider = createOpenRouter();
const callbackUrl = new URL('/LocalCut/', location.origin).href;
const { authorizationUrl } = await provider.beginAuthorization({ callbackUrl });
// From an explicit Connect action:
location.assign(authorizationUrl);
```

Use the existing static page as the callback, `/` for a root deployment or `/LocalCut/` for GitHub Pages. The workspace handles the callback on the same static page and immediately removes its OAuth query fields. On return, capture the full URL, then remove `code`, `state` and OAuth error fields from the visible address before asynchronous work or analytics. Keep any original non-OAuth query parameters unchanged:

```ts
const callbackUrl = location.href;
const clean = new URL(callbackUrl);
for (const name of ['code', 'state', 'error', 'error_description'])
  clean.searchParams.delete(name);
history.replaceState(history.state, '', clean.href);
const provider = createOpenRouter();
await provider.completeAuthorization({ callbackUrl });
// provider.status() is now { connected: true }; no raw key is returned.
```

The helper rejects fragments on returned provider callbacks and verifies the registered callback origin/path/query, state, expiry and single-use record before exchanging the code. Denial is handled without assuming OpenRouter supplies state on denial. Invalid or failed callbacks require a fresh connection attempt. Storage unavailable means an explicit auth failure; there is no silent insecure fallback. Host-specific storage can be supplied via `oauthStorage` or individual authorization options. Do not put credentials in project JSON, preferences, backups, URLs, exception text or telemetry. The workspace uses only the dedicated credential record described below. No management key is used. `setKey` is an alternative for an existing user-owned OpenRouter API key. `status().connected` reports local credential presence, not verified credit or account health.

`disconnect()` clears the runtime key, removes any opted-in saved credential and owned pending OAuth state, and aborts in-flight work. `dispose()` retires the runtime and makes the client unusable, preserving the saved credential for reload. Neither operation revokes the remote key; users control revocation and spending limits in OpenRouter. Browser-local storage is not an encryption vault and cannot protect a saved or active key from malicious same-origin scripts, browser extensions or an already compromised page. PKCE protects the authorization exchange, not an unlocked browser runtime. No encryption vault is included.

## Protocol and tool boundaries

The adapter sends requests only to fixed HTTPS OpenRouter endpoints with omitted browser cookies, no referrer and no redirects. `listModels()` fetches the current catalog explicitly. Every chat validates the selected model supports tools before sending. No default model or silent model/provider downgrade is selected. User-selected provider aliases beginning with `~` are supported; their underlying model can change at OpenRouter. `openrouter/auto` is not selected or accepted. Requests use `provider.require_parameters: true` and `provider.data_collection: 'deny'`; a policy or capability failure is surfaced. Chat exposes no media inputs, plugins, server tools or arbitrary endpoint options. The separately consented indexing path below accepts generated local evidence.

Provider reasoning text and signed/encrypted reasoning details are retained as opaque conversation state for subsequent tool rounds. They are not emitted as user-visible text events or interpreted as tools.

Each `tool` event carries a locally generated `callId`, name and phase. After schema validation, the start event includes the parsed input; terminal events include the redacted result or a safe structured error. Match updates by `callId`, including repeated calls to the same tool. Permitted details are retained in full; invalid arguments and provider continuation data are never exposed. The workspace renders these as independently expandable calls.

Streaming uses validated UTF-8/SSE parsing and handles comments, split network chunks, CR/LF boundaries, multiline data, incremental tool arguments and final usage accounting. The adapter requires a complete terminal response and `[DONE]` before exposing executable tool calls. Incomplete, malformed, refused and provider-error streams fail. A standalone adapter never retries a charge; service failures never switch providers. Abort cancels local consumption and HTTP work; whether upstream billing stops depends on the provider.

## Incremental domain skills

Every turn starts with `load_skill`, `inspect_project`, `inspect_capabilities` and `inspect_proposals`. The fixed catalog always describes all six known domains, including domains whose services are unavailable in the current host. Loading guidance grants no execution authority. It lets the assistant distinguish a missing executor from unloaded tools or permission and explain a specific user step instead of denying the feature.

The trusted system context carries a complete `capabilityMap`, rebuilt each round from the same typed rules in `tools.ts` that own tool declarations and action variants. It includes every canonical tool/action, `supported` host capability, `available` current-round access, `requiredSkills`, and blockers with safe next steps: `host_unavailable`, `sharing_disabled`, `skill_not_loaded`, or an explicitly configured `caller_budget`. `loadedSkills` resets each turn. The initial context also identifies current sharing flags, authorized asset IDs and user-owned controls; it contains no additional private content. `inspect_capabilities` exposes this same map alongside canonical edit fields/rules and detailed indexing disclosure.

Guidance directs every workflow to its mapped domain, handles compound requests across domains, and continues permitted portions when a private read or user-owned step blocks another part. Export still requires a native codec probe; transcription readiness, model preparation and inference remain separate. Discovery never promises native readiness. Known rejected tool/action calls return structured next-round recovery from the same map. A rejected action identifies its specific domain even when another skill already exposes `propose_action`. Unknown calls point back to fixed discovery without echoing invented names or enabling them. The host never loads a skill, forces extra provider retry rounds, retries a provider refusal or executes a proposal on the model's behalf. Normal tool rounds remain part of the user-requested workflow; failed paid requests do not gain automatic retries.

| Skill           | Guidance and tools enabled                                                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `editing`       | All canonical timeline, clip, audio, text/caption, effect, group and transition edits; asset/timeline/capability inspection, validation and edit proposals             |
| `export`        | Browser codec preflight and local export proposals; guidance always loadable; probing/proposals require engine export support                                          |
| `transcription` | Local readiness, preparation/inference proposals and shared transcript reading, individual tools/actions remain filtered by engine support and sharing consent         |
| `indexing`      | Selected/project media inspection and approved derived-evidence indexing; guidance always discoverable; proposals require a trusted executor and live indexing consent |
| `history`       | Undo/Redo guidance always loadable; each proposal is filtered by engine support                                                                                        |

Guidance modules are dynamically imported from a fixed local registry when `load_skill` succeeds. No user/provider URL, arbitrary code or external skill installation is accepted. Full skill text is returned through the ordinary tool result; it is absent from initial request context. Repeated loads in one turn return `already_loaded` without duplicating guidance. Loading a skill starts no engine service or model download and grants no edit approval or additional sharing consent.

The host rebuilds tool definitions for each model round. A successful load enables its tools on the **next** round. The current response's declared tools and allowed action variants remain frozen, so a load cannot authorize sibling calls in that same response. Guessed/unloaded tools and unsupported/unloaded action types are rejected before inspection, validation or proposal execution. `propose_action` contains only the loaded domains' supported schema variants, with a matching runtime check. Skill loading observes cancellation/disposal and any explicitly supplied caller budgets. Loaded authority resets on every turn; retained history keeps load receipts instead of full skill instructions and never authorizes current tools. Reload the relevant skill after user approval or for any follow-up request.

The tool audit retains the existing engine-backed operations behind those domain boundaries. Core inspection stays available for orientation and confirmed approval results; no mutation, arbitrary network, filesystem or code-execution tools are exposed. `inspect_capabilities` includes the skill catalog, canonical supported service actions and indexing support, permission blockers, sharing disclosure and asset scope. Service discovery grants no execution authority; loaded proposal schemas still enforce permission. Consumers of `ai.js` keep the same assistant API, but scripted providers must issue `load_skill` in a preceding round before domain calls.

The assistant exposes the following tools incrementally. Arguments derive from canonical edit/action schemas; optional tools and action variants require both the matching skill and supplied engine capability. The typed access registry requires an explicit discovery rule for every canonical tool and action; declaration and recovery cannot omit a newly added variant silently.

## Prompt and skill maintenance

Repository `AGENTS.md` guides contributors; runtime chat instructions are owned by `assistant.ts`, the fixed domain catalog in `skills.ts` and lazy `skills/*.ts` modules. Keep their responsibilities clear:

- The system prompt owns role, trust/privacy/approval boundaries, concise replies and the general discovery → inspect → validate/propose workflow and trusted execution policy (workspace requested execution; default headless review). It directs the model to current facts, handles compound/partial requests and explains failure/resume. It must not infer global feature absence from filtered tools or invent private facts.
- Catalog descriptions own domain selection. Keep them searchable by the task a user wants to perform. All known guidance remains reachable; loading never grants a service, consent or approval.
- The typed access registry owns current tool/action support, permissions and recovery. Populate trusted per-round context from it; do not duplicate capability booleans or supported-method lists in prose. `context.ts`/index context remain the owners of private-data redaction and selected-asset scope.
- Lazy domain guides own conditional procedures, native/readiness checks, data/time units, field-preservation rules and concrete next steps. Explain missing host support, missing sharing and invalid/current state separately. Continue supported portions rather than reject a compound goal wholesale. Approved results and fresh inspections establish completion; a proposal or loaded guide does not.

For a prompt/skill change, walk through a realistic request, an unloaded or wrong-domain call, a private-data blocker, invalid input/native readiness and a fresh/resumed turn. Verify that recovery reaches a declared supported tool while frozen-round, scope, privacy, cancellation and approval boundaries remain intact. `assistant.test.ts` contains the complete support/loading/sharing matrix and recovery cases; `ai-skills.spec.ts` exercises wrong-domain recovery, speech/Storyboard inspection, public font discovery, blocked transcript reads, approved persisted editing and fresh-turn authority through production entries at both bases. Native exports/history and indexing have their linked integration scenarios in the feature inventory. Requested-mode regressions additionally cover sequential revisions, text clarification/reply, service cancellation, committed results after interrupted narration, asset scope and failed-paid-action retry blocking. String checks prove guidance is present; controlled providers prove tool/engine paths. Live model adherence and output quality require separately authorized real-provider evidence.

## Proposal execution

A completed turn publishes cloned proposals with host-generated IDs and immutable internal requests. `getProposal()` returns a copy; editing it cannot change what approval executes. Every proposal carries `batch.projectId`, `batch.expectedRevision`, and a stable `batch.requestId`. Ordinary edits retain their complete command batch. A service/history proposal carries an `action` and an empty `batch.operations` array used only as a revision envelope; that array is never sent to `commands.apply`.

`applyProposal(id)` remains the compatible edit-only API and returns its receipt. The workspace uses `approveProposal(id)` for any card:

```ts
const proposal = assistant.getProposal(selectedProposalId);
// Only from an explicit Apply/Approve action, after showing its action/settings:
const result = await assistant.approveProposal(proposal.id);
if (result.kind === 'export') {
  const artifact = assistant.exportArtifact(result.artifactId);
  // Keep artifact.file local. Offer a separate browser Save action.
  offerSave(artifact.file, result.name);
  // After Save or dismissal:
  await artifact.dispose();
}
// For a running export, transcription, indexing or model-preparation card:
assistant.cancelProposal(selectedProposalId);
```

`approveProposal` returns a discriminated result: an edit/history receipt, local export metadata and artifact ID, transcript ID/source/cue count, index run ID/asset ID/scene count, or model-preparation readiness. Export files and storage paths never enter provider context. Progress appears in `proposal_progress` events and `proposal.progress`; worker details and raw errors are excluded. Export artifacts remain owned by the assistant until explicitly disposed or the assistant is disposed. Disposal cancels active service jobs and releases owned export artifacts; persisted index runs remain available in the media library. A service retry is always another explicit user approval, never an automatic model retry. Preparation and inference are separate approvals; an unprepared transcription fails without automatically downloading a model. Approving local transcription does not opt its text into remote context. Its new transcript can be linked to the source clip without sharing text, or read by the model only when `includeTranscripts` is enabled.

Edits and history delegate to the engine's atomic revision checks, persistent idempotency receipts, asset validation, and history. Export validates the authored revision before starting and the actual captured revision before publishing. A concurrent project edit produces `REVISION_CONFLICT` and requires a new proposal. Concurrent approval of one proposal shares one result; approving a completed export does not encode it again. Cancellation/disposal does not roll back an already committed edit or persisted transcript. No model tool can approve or cancel another proposal, trigger Save, or bypass the host approval action.

Atomic edit and history commits cannot be cancelled after submission. `cancelProposal` rejects those proposal types and treats a late cancellation of a completed service job as a no-op, preserving its artifact. Consumers should show cancellation only on running export, transcription and preparation jobs.

| Public engine family    | Assistant access                                                                                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Commands                | Every edit operation through a dry run and reviewed batch; Undo/Redo through reviewed actions                                                                       |
| Export                  | Read-only native preflight; reviewed encoding; user-owned Save and artifact disposal                                                                                |

The assistant stages proposals until the whole turn succeeds. A fatal malformed response, cancellation or turn-budget error discards staged proposals, leaving project state unchanged. Recoverable tool errors return sanitized results to the model for correction within the same budget; invalid operations are never staged. All streamed text, arguments, names and transcript content remain untrusted data. The model cannot fetch arbitrary URLs, run JavaScript, import files, read credentials, delete projects, clear caches, expand asset selections, or approve its own proposal. Consumers should distinguish streamed narration from a completed proposal. Sessions permit one active turn, retained history, explicit `clearHistory`, disposal, turn cancellation, and listener unsubscription. Cancellation retains the unfinished user request, partial narration and confirmed observations/receipts as marked text context for every subsequent explicit turn, regardless of wording. The model interprets the latest message with this history and follows any changes of direction; no continuation-phrase matching selects or injects context. A `continuation` event publishes that canonical text and its index-scope marker separately from tool display events, including receipts committed just before cancellation. It never retains unmatched executable calls, unfinished proposals or loaded skill authority. Terminal replies with neither visible text nor tool calls fail with `RESPONSE_INCOMPLETE` and `reason: empty_response`, rather than completing silently; no automatic retry follows, and earlier committed actions remain saved.

## Privacy and resource limits

The user's prompt and structural project metadata are sent only by explicit `run()`. Defaults withhold project/asset names, overlay/caption text and transcript content. `includeAssetNames` also includes the project name. `includeText` enables overlay text and caption cues; `includeTranscripts` enables the transcript tool. Headless callers must obtain authorization before enabling these options. The workspace derives all four flags, including `includeCaptureMetadata`, from the connected OpenRouter account under the [connection terms](#openrouter-connection-terms); disconnected configurations do not grant them. The prompt itself can contain sensitive information; redacting project fields does not redact user-entered text.

Raw source files, frame images, thumbnails, PCM, private browser files, complete backups and API keys are never supplied to the assistant tools. Editor media processing and local Whisper inference remain local. OpenRouter is a remote service: unlike local transcription, this feature sends selected text and metadata off the device. `data_collection: 'deny'` filters upstream provider data policies; it does not guarantee zero retention by OpenRouter or override the user's account logging settings. Zero-retention routing is not promised. See [OpenRouter data collection](https://openrouter.ai/docs/guides/privacy/data-collection) and [provider routing](https://openrouter.ai/docs/guides/routing/provider-selection).

The workspace imposes no default or hard application ceiling on assistant rounds, tool calls, operations per proposal, retained proposals/history, selected asset count, context/request size, response text/reasoning, streamed tool payloads or chat duration. It does not force a tool-free reply or stop an active turn after an arbitrary budget. Complete permitted tool-event details are retained without hidden truncation. Complete conversation exchanges remain available until the user clears history or retires the session; automatic context compaction is disabled under the newer no-cap preference.

Provider/model context, output, rate and spending limits still apply. OpenRouter requests use the selected model's advertised maximum completion allowance when available, without subtracting a local byte-based input estimate; otherwise they omit the output parameter. Providers perform actual tokenization/context admission. The model picker accepts every explicitly configured tool-capable model, regardless of context length. No default chat HTTP timeout is installed; cancellation, disconnect and disposal abort consumption.

Headless API callers may explicitly provide positive safe-integer `AssistantLimits` or `requestTimeoutMs` budgets; every omitted field remains uncapped and no fixed maximum ceiling is imposed. These compatibility controls are not workspace defaults. An explicitly requested round/call budget permits one final tool-free response; an oversized call batch executes no calls, and finalization cannot grant tool authority. Staged proposals publish only after validated terminal completion. Context/byte/output limits apply only when the caller explicitly supplies them. Provider failure or cancellation never automatically retries a paid request. Non-chat authentication, catalog discovery, indexing and speech retain their separate contracts. Complete terminal/protocol/schema validation, privacy, explicit proposal approval and stale-revision checks remain enforced. Provider usage/cost remains visible; the browser and provider own physical capacity.

Errors use stable `AiError.code` values: authentication/expiry, credits, rate limits, network/timeout, unsupported models, malformed/incomplete responses, context/tool/response limits, forbidden tools, rejected edits, stale revisions, cancellation, busy state and disposal. Provider response bodies are not surfaced as error text, since they can echo credentials or private content. HTTP status and bounded retry-after metadata may be provided. A retry on the same provider is always an explicit caller action; user-configured routes may fail over once per listed provider before output.

OpenRouter chat retains `data_collection: 'deny'` and `require_parameters: true`. It sends `parallel_tool_calls: false` only when the selected model advertises that parameter, so strict routing does not exclude tool-capable endpoints for an optional control. Local tool execution remains sequential even when a model returns several calls. Compatible endpoints retain their existing request settings. HTTP 404 prompts a model/catalog check, HTTP 413 prompts a smaller message or new chat, and other request rejections include their status without exposing the provider body. Connection alone does not prove model availability under provider-account routing or privacy restrictions.

References are capped at 15 MiB decoded and never contain automatically selected project media. Delivery instructions are unavailable on this route because OpenRouter does not forward them for Fish. No fallback provider receives reference audio. Missing or unsupported references fail before submission; queued requests preserve their immutable reference after preset changes. Reference synthesis can approximate the same speaker but cannot guarantee identical cadence/audio or live quality without an authorized provider listening test. Legacy settings-only presets remain distinguishable.

## Track editing

The progressive `editing` skill exposes every track command through the canonical edit schema: `addTrack`, `updateTrack`, `duplicateTrack`, `reorderTrack`, `clearTrack`, and `removeTrack`. Capability inspection describes output/lock rules; project and timeline inspection include structural state and evaluated visible/audible flags. Track names follow the existing `includeAssetNames` consent and are withheld by default. No new sharing permission or media upload is introduced. See [track API contracts](api.md#track-operations).

Track edits are revision-bound proposals with explicit user approval. A locked track cannot be edited through AI; requested unlocking must be an explicit proposed operation. Clear/delete summaries should identify the removed contents. Loading the skill or validating a batch performs no edit and grants no approval.

Generated speech timing uses [the shared transcription facade](api.md#generated-speech-timing). Every new Generate uses the STT route configured in AI settings and submits only the newly generated audio to that route, with possible additional charges for remote STT under the OpenRouter connection terms. The speech dialog has no separate phrase-timing selector or informational section. Local Whisper requires explicit preparation. This never selects project source audio, downloads a model automatically, or grants transcript-text sharing. The task pins its STT route snapshot as well as the synthesis route, so retry cannot silently change recipients/models. Stored generation metadata omits reference audio bytes. Agents with explicit transcript sharing can read recognized phrases, original authored script and synthesis identity through a referenced clip's `transcriptId`. Prefer padded `cues` for editing handles; `speech.measuredCues` retain the unpadded measurements in rendered-source time. Interpret both through the clip's source trim/speed and timeline placement. ASR and proportional WSOLA timing are estimates.

### Chat context and capacity

LocalCut sends complete permitted conversation/tool exchanges without a fixed token, message-count or byte ceiling and without automatic truncation/compaction. It does not exclude tool models by a minimum context threshold. Provider tokenizers and advertised/native model capabilities determine acceptance; an exhausted provider context remains a provider error requiring an explicit new request. Clearing history or retiring shared index scope clears earlier context. Text-to-speech opens from Media through the existing connection; only Generate submits synthesis.

## Single connection and verification

The workspace retains one OpenRouter profile ID so a migrated connection can reuse its existing browser-local credential namespace. New connections use the legacy `openrouter` namespace. Disconnect confirms removal of the saved key and pending authentication, ends context sharing, cancels requests and leaves non-secret model choices for explicit reconnection. Cross-tab key removal retires the active connection.

Verify explicitly checks OpenRouter's authenticated current-key endpoint. It sends no project data or inference request and does not prove paid-model access or generation quality. Credentials and pending authentication remain excluded from portable backups.

### Speech model discovery in connection settings

These settings changes add no editing operation or assistant capability; the existing shared editing/transcription/speech paths remain intact.

Storyboard inspection starts with element counts in `inspect_project`; only the loaded storyboard skill exposes paginated geometry inspection. Raw media, links and embeds are never available. `includeText` opts labels and frame names into remote tool results; without it, geometry and presence flags are available. A model can propose new text supplied by the user or patch geometry while preserving withheld labels. The skill does not grant approval, connection or paid-request authority. Domain guidance remains a separate lazy module and resets each turn.

## Capture metadata access and sharing

`ContextPolicy.includeCaptureMetadata` defaults off for headless clients and remains caller-controlled. In the workspace, actual OpenRouter connection enables capture dates/GPS together with text, names and transcripts, including on credential restoration. Disconnecting OpenRouter retires the chat and cancels active card indexing. The explicitly marked authorized chat scope recovers previous sharing variants while preserving project/model/provider identity; without an OpenRouter connection, the existing unshared scope remains isolated.

`inspect_asset(assetId).capture` is the authoritative discovery path for allowed project/attached assets. The system prompt and tool description identify `time.value/source` and `location.latitude/longitude/altitudeMeters/source`; indexing guidance points to the same fields. Unknown or withheld fields must not be guessed; absent offsets must not adopt the browser timezone. Metadata is untrusted source data, not instructions or verified evidence.

Local analysis retains `run.source.capture`. With capture sharing enabled, the dedicated indexer appends these structured facts to scene and summary prompts and records `captureIncluded` in each manifest. Labels are asked to keep dates/GPS out of descriptions, but the run is still marked `captureShared` before transport. Without capture permission, chat excludes that entire run from catalog, search and read, preventing inferred/repeated details in labels from bypassing redaction. Retrying an incomplete capture-informed run with sharing off fails before labeling traffic: enable capture sharing to resume that run, or start a new index without capture context. An already complete run can return locally without provider labeling. Indexes made without capture context can still share their descriptions while their source capture fields remain hidden. With permission, catalog/search/read expose structured capture alongside saved descriptions, and date/coordinate strings participate in search. Existing runs without capture facts remain usable. Remote provider understanding/label quality has not been proven by deterministic transport tests.

## Restored chat history

`createAssistant({ restoredTurns: [{ id, user, assistant, interrupted? }], ... })` accepts validated text-only exchanges from the caller's matching project/model/sharing scope. Use either an opaque branch or restored turns, never both. It restores only the newest caller-configured `maxHistoryTurns` exchanges; no default history cap or compaction applies. Construction performs no provider work. Historical protocol tools, loaded skills, proposals, approvals, asset allowlists and sharing consent are absent; each new request rebuilds current project context and authority. Interrupted exchanges retain their unfinished request and explicitly marked partial text/confirmed progress, and cannot be branch targets. Completed response IDs can be branched through the existing branch API, including preceding interruption context. The workspace restores completed exchanges from local display records; interrupted exchanges use assistant-owned canonical continuation metadata with matching saved index provenance. Display tool rows and partial narration cannot reconstruct interrupted model context because they may predate retirement or omit a late committed receipt. The last unfinished user request remains recoverable after a crash or from an older saved record, without unverified historical observations. Completed exchanges outside the retained IDs cannot reenter model context. `restoredIndexScope` carries the captured local index-run marker; missing or changed evidence retires index-bearing history before the next request, including interrupted observations.

## Media folder assistant access

The editing skill includes `inspect_library` and the `library` service action. `inspect_library` discovers stable folder/entry IDs, parent IDs and the separate library revision; asset entries are restricted to the selected/project asset allowlist. File and folder names remain behind `includeAssetNames`. No filesystem handles, bytes or media upload are exposed.

`propose_action { action: { type: "library", expectedRevision, operation }, summary }` uses the canonical library operation schema for create, rename, move, copy, trash and restore. Capability discovery distinguishes an unloaded editing skill from a missing host library. Every descendant asset must be selected or referenced before a folder mutation can be proposed/executed. Execution rechecks both project and library revisions and the current asset scope; default headless approval and workspace requested execution retain their existing contracts. Upload selection and download Save stay user-owned. Library organization does not change the timeline revision or its Undo history.

Feature-access inventory addition: Media folder navigation/management → `inspect_library`, canonical `library` action and shared `editor.library`; uploads/download Save → explicit user filesystem actions.
