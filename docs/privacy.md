# Privacy and data flows

LocalCut is a static browser application. It has no application backend or cloud project sync. That does not mean all network traffic is absent: the browser fetches the application, explicitly prepared inference assets and optional provider requests. Hosting and provider services may process their own request/account information under their policies.

## Data boundaries

OpenRouter API requests identify the public LocalCut application through fixed attribution headers, which can associate usage with its public OpenRouter app analytics/rankings. Inference requests additionally carry opaque chat, index-run or operation IDs for grouping; these do not contain project names, page routes, prompts or a global user identifier. Related chat requests reuse the saved chat UUID, including after reload; new chats and forks have independent IDs. Generation IDs and token/cache/reasoning accounting returned by the provider remain available locally. See the [OpenRouter request contract](ai.md#request-management-and-documentation-audit).

| Action or data                                        | Where it goes / persists                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Imported originals, editing, preview and video export | Browser-local media processing; originals in OPFS, project records in IndexedDB                                                                                                                                                                                                                                                                                 |
| Saved projects, versions and workspace preferences    | This browser profile and origin; no automatic cross-device transfer                                                                                                                                                                                                                                                                                             |
| Default local Whisper transcription                   | Selected audio stays local; explicit preparation downloads pinned model/runtime assets into the named cache                                                                                                                                                                                                                                                     |
| Chat                                                  | User prompt and permitted project context go to the selected OpenRouter chat model; a connected OpenRouter account enables names, text, transcripts and capture metadata under the connection terms, including after reload                                                                                                                                     |
| Asset indexing                                        | OpenRouter connection plus explicit Index or user chat request can send generated stills, audio/video excerpts with sound to the selected OpenRouter model; it does not send the original source file                                                                                                                                                           |
| Text to speech                                        | Explicit Generate or an authorized narration chat request sends the authored script, voice, languages and delivery instructions through the selected OpenRouter speech model; resulting audio becomes a local asset when added; explicitly cloning a saved generated or composer-dictation speaker can send that selected reference and its matching transcript |
| Remote transcription                                  | An explicitly selected OpenRouter STT model and requested transcription job send selected decoded audio to OpenRouter; local Whisper remains the default                                                                                                                                                                                                        |
| Portable backups                                      | The user downloads selected preferences/projects/versions and optional originals; provider credentials and sharing consent are excluded                                                                                                                                                                                                                         |

Each service has one selection and never fails over. Remote transcription discloses OpenRouter as the recipient before sending selected audio; local Whisper keeps source audio in this browser. See the [AI contract](ai.md#openrouter-service-selections).

## Credentials and consent

The one OpenRouter key persists in a separate browser-local record and may restore the connection/catalog after reload. Disconnect removes that saved key and pending authentication.

Browser localStorage can be read by scripts executing on the same origin; this is not an OS-protected credential vault. Do not connect sensitive accounts on shared computers or untrusted copies of the app. Prefer a dedicated origin for self-hosting. Build-time variables cannot safely conceal a provider key in a static application.

Connecting OpenRouter accepts the visible [connection terms](ai.md#openrouter-connection-terms): project/media names, overlay/caption/storyboard text and frame names, authored coding sources/file paths/execution output, source transcripts and embedded capture dates/GPS are enabled for the selected OpenRouter model while connected, including after reload. Explicit Index or chat indexing also authorizes derived evidence and saved labels. Connection, import, navigation and reload do not submit chat or indexing requests. Disconnecting OpenRouter retires this context. Headless clients retain caller-controlled opt-ins. Chat titles, messages, tool activity, unsent drafts and attachment references persist locally in IndexedDB. The OpenRouter-authorized scope recovers old sharing/indexing variants with matching project/model/provider identity. Restoration sends no requests and restores no execution authority. Chats remain excluded from portable backups. See [workspace behavior](workspace.md) and [chat storage](storage.md#local-chat-sessions).

## Retention, removal and recovery

Browser storage is subject to quotas, eviction and user deletion. Keep originals and portable backups outside the app, and verify a backup in a separate profile before clearing data. Use supported app operations for project/asset removal; manual IndexedDB/OPFS edits can break ownership and recovery invariants. Clearing a model cache does not delete saved transcripts, media or edits. See [storage](storage.md) and [transcription](transcription.md).

Disconnecting locally does not necessarily revoke a provider-issued credential or erase data already sent to a provider. Use provider account controls for revocation/remote retention. A downloaded export or backup is a separate file and remains until you remove it. Browser site-data clearing is destructive and affects the entire origin; export first and understand the scope.

Do not publish private media, project archives, transcripts, callback addresses, tokens or raw storage/network traces in support reports. Use generated samples and redact screenshots/logs. Follow [SECURITY.md](../SECURITY.md) for suspected data disclosure or credential vulnerabilities.

Provider HTTP rejection bodies are read locally with a 16 KiB and one-second diagnostic budget. Only fixed machine rejection categories and recognized parameter names enter local errors; provider messages, arbitrary fields and raw metadata are discarded. SSE errors use the same allowlist. Errors also identify whether the initial goal definition or completion check failed. These diagnostics do not initiate another request or disclose new project data. Unknown or unreadable diagnostics retain the original HTTP status.

Embedded capture dates and GPS are retained locally with imported assets and backups. A connected OpenRouter account authorizes their use in remote chat inspection and explicit indexing prompts. Without that grant, capture facts and labels generated with capture context are withheld. No location lookup or browser geolocation request runs. Local asset details remain available. See [capture access](ai.md#capture-metadata-access-and-sharing).

## Chat exports

Explicit Export chat captures a local transcript and unsent draft in a durable task, including displayed tool details, proposal records and local attachment IDs/names. Treat the downloaded archive as private conversation data. Generation sends nothing to a provider and excludes credentials, opaque continuation and media files. Queue inputs and outputs stay in browser storage until their task is removed or site data is cleared; saved downloads are user-owned files.

Workspace chat treats the user request as authorization and uses text questions only for missing information or ambiguous intent. No approval UI is shown. Headless clients retain review mode by default; see [requested execution](ai.md#workspace-requested-execution).

Voice presets store settings and provenance locally, separately from generated or composer-dictation reference audio and transcripts. Successful composer dictation recordings also persist as local Media assets; cancelled/error/empty captures are discarded. The Dictate tooltip discloses recording retention and browser speech-service processing. The agent lists permitted metadata, with headless name/text redaction, and can clone a specifically selected saved generated or composer-dictation voice only when requested. This grants no access to arbitrary original project recordings or another project's media. Reference-model reuse never accepts arbitrary audio bytes from a tool call.

## Browser coding execution

The project coding directory contains authored sources and generated files. Guest JavaScript runs in QuickJS inside a terminable worker, with only virtual project-file bindings; browser globals, provider credentials, other projects, internal journals and immutable Media originals are absent. The browser shell uses the same virtual filesystem with networking disabled. Runtime JavaScript/WASM is embedded in pinned local deployment chunks, loaded only for coding work; no runtime CDN, account or backend is required. Generated binary bytes stay local until the user requests the existing media/indexing/transcription paths. Authored UTF-8 sources, paths, search results and console output may enter the selected chat model under the coding context grant. Shell stdout and script logs are user-program output; avoid writing secrets into this workspace.
