# Local storage and recovery

Opening createEditor explicitly creates IndexedDB localcut-v1 and OPFS localcut/. Model preparation uses localcut-asr-v1 in Cache Storage. Tests pass a separate namespace. All paths on a GitHub Pages origin share storage; cleanup must remain scoped to LocalCut resources.

Appearance uses the separate, versioned localStorage key `localcut.appearance.v1` containing `{ version: 1, preferences }`. It stores only enumerated UI choices, not credentials, media, project data or chat. Reading appearance at startup does not initialize editing storage. Root and `/LocalCut/` on the same origin share this preference. Storage events synchronize tabs; reset removes only this key. Unknown versions and invalid fields use safe defaults; read/write failures leave session customization usable and show an unsaved notice. Appearance is outside project backups and does not require a project-schema migration.

Workspace preferences use `localcut.workspace-preferences.v1` with `{ version: 1, preferences }`. The whitelist is `chatWidth`, `chatCollapsed`, `mediaOpen`, `exportFormat`, `aiModel`, and non-secret `aiProviders`; credentials, sharing consent, content and runtime state cannot be hydrated or saved through this owner. Reads precede rendering and do not initialize IndexedDB/OPFS or AI. Writes patch the latest saved record to preserve unrelated choices; storage events read the current record instead of replaying stale event payloads. Simultaneous writes remain last-writer-wins (localStorage offers no transaction across read/modify/write). Failed writes preserve session choices for retry and trigger an actionable toast. Finite widths are rounded/clamped to 280–560, booleans/enums and bounded model identifiers are validated, and malformed/unknown versions fall back to defaults. Same-origin root/Pages tabs share choices; removing this key resets workspace defaults in other tabs, and unrelated keys are ignored.

`aiProviders` stores at most one non-secret OpenRouter profile and one model/voice selection per service. Legacy multi-provider settings are normalized on read/import; removed primary STT services return to local Whisper. Credentials, callback URLs, authorization codes and tokens never enter this whitelist or backups. The retained OpenRouter account keeps its existing credential namespace; startup retires other OpenRouter keys, removed ChatGPT token authority and pending flows locally. Original media, editing records, chats and speech outputs are not deleted.

Workspace and appearance records remain separate so Appearance Reset removes only its existing key. Both are outside project snapshots, versions and legacy project JSON backups; selective workspace backups can include either preference group, with no project migration. Rollback to older code ignores the workspace key and preserves project storage. See the [preference audit](workspace.md#local-user-preferences) for inclusion/exclusion decisions.

The disposable `localcut.project-catalog.v1` localStorage record contains `{ version: 1, projects }`, where each summary has only `id`, `name`, `clipCount`, `durationUs` and optional `archived`. Reads do not initialize editing storage. The cache is limited to 1,000 entries and 524,288 serialized characters; unknown versions, duplicate/invalid fields, oversized records and unavailable storage fall back to normal loading. Successful current catalog reads replace it, including empty lists and removals; superseded reads cannot publish. Failed refresh keeps the previous visible summaries and reports the existing toast. This cache is excluded from backups and preferences, holds no documents/media/credentials, and never supplies an editable snapshot. Older code ignores it.

The versioned localStorage record `localcut.recent-project.v1` stores `{ version: 1, projectId }` after successful authoritative project activation, including create/import. It contains only a validated local identity, remains outside preferences and all backups, and is shared across root/Pages tabs on the same origin. Initial bare navigation reads it once and replaces the route to restore that project through the engine. Explicit URLs and OAuth callback restoration take precedence; fresh startup and malformed/unavailable localStorage remain inert. Authoritative NOT_FOUND clears only a matching pointer; other storage failures retain Retry. Older code ignores this record.

IndexedDB contains projects, 100 undo/redo snapshots, lifetime idempotency receipts, metadata, transcripts, derivative records, and journals. A document/history/receipt change uses one atomic transaction with a revision check. Unsupported schemas and malformed imports fail without replacing a saved project.

Project records also contain an append-only `versions` array, separate from the bounded undo/redo stacks. Each entry has a stable ID, increasing number, creation timestamp, kind (`initial`, `autosave`, or `restore`), complete project snapshot, and optional `restoredFrom` version ID. Create/import initializes a baseline; opening a legacy record adds a baseline of its current normalized state without changing its edit revision or undo/redo history. This additive record extension does not change the IndexedDB database version. Existing versions are never normalized again or changed by edits.

The editor schedules a trailing one-second autosave after committed edits, undo/redo and project notifications. Saving uses an atomic transaction on the authoritative stored document and deduplicates its current revision. Switching projects, entering version browsing and disposing flush pending saves; opening recovers a working revision left by a tab closed before its timer. Edits are durable before the debounce, so a forced browser close cannot lose committed editing data. Multiple tabs can save the same revision without duplicate versions. Storage failures are reported; the working project remains intact and saving can be retried.

Restoration verifies the authored current revision and receipt content, preserves any pending current state as a version, then commits the selected historical state at the next edit revision and appends a `restore` version in the same document/history/receipt transaction. It is undoable; retrying the same request replays its receipt. Original files referenced only by historical versions remain retained. Project deletion removes its versions alongside its document; Legacy project JSON backups contain the current state only; workspace/project transfer archives can include the complete saved version history.

Rollback to older application code retains the current project and media, but that older writer does not preserve the additive version field when committing edits. Export a current JSON backup and retain an origin-storage backup before such a rollback; do not run old writers against projects whose version history must be retained.

Asset display-name changes compare the expected stored name and commit metadata in one IndexedDB transaction; they do not advance project revisions or rewrite originals. Metadata is shared by current projects and saved versions. Removing current-project clip references retains originals and saved index evidence for undo and version restoration.

Looping clips add optional loop offsets to the version-one clip document; project versions, backups and history retain them without an IndexedDB migration. Older strict readers cannot read those clips. Retain a compatible reader or export rendered media before rolling back to an older app.

Original media is immutable OPFS content identified by asset ID. An import journal precedes file mutation. An asset becomes ready only after the file finishes; failure removes partial content. Relink accepts a missing original with matching metadata; it does not overwrite a ready source.

Imports commit ready metadata and their publication journal marker in one IndexedDB transaction. Transcripts likewise commit only after inference succeeds and their source bounds are validated. Cancellation aborts either transaction while it is pending. After a successful commit, a late cancellation cannot remove the original or transcript and the job returns the committed result. Export files and frame bitmaps have no such editing-data commit: cancellation before delivery removes the finished export or closes the bitmap before reporting CANCELLED. Delivered artifacts remain the caller's responsibility to dispose.

Exports and derivatives also journal their temporary files. Explicit engine opening recovers abandoned journals under Web Locks. An active job's lock prevents another tab from deleting its work. Completed ready originals survive recovery. File reads report MISSING_ASSET with a relinking path when needed.

Derivative records track size/access time. Cleanup uses an LRU budget of 512 MiB, reduced for available origin quota, and reserves estimated space before imports, derivative conversion, and exports. A quota failure cleans the partial output, evicts eligible owned derivatives, and retries once; active reader locks and originals remain protected. Active PCM readers pin their asset resources. Cache eviction never deletes originals, edits, or transcripts. Quota exceptions become QUOTA_EXCEEDED. The browser can still externally evict origin storage, so retain source backups.

Waveform peaks, thumbnail tiles and complete contact sheets share that derivative store and budget. Keys include algorithm version and asset ID, plus bin count for peaks, source timestamp/width for tiles (still-image timestamps normalize to zero), or a hash of the ordered timestamps/width for sheets. Source identity contains original OPFS size/last-modified time and decode-relevant metadata; names and timeline edits do not change it. Records also retain MIME type and SHA-256 for these small display artifacts. Reads verify identity, size and hash before reuse and do not open a decoder or canvas on a hit. PCM/proxy records also verify source identity and file size; older records lacking identity rebuild once. Relink removes all prior derivatives under the exclusive original lock, including replacements with identical metadata.

Generation holds the original's shared lock and the derivative's exclusive lock across read/compute/write, so matching requests serialize across workers/tabs and eviction/relink cannot race readers. Each display file is journaled under a unique active job lock. Interrupted writes recover through the existing journal; cancellation before completion removes the partial file/record. Cache quota recovery retries writing the already computed blob once, without rerunning the computation. Failed LRU timestamp writes or obsolete-cache cleanup do not block readable results or fresh computation. If disposable display-cache persistence remains unavailable, the computed pixels/peaks still return for the current session. Missing originals still require relink. Contact sheets acquire the original lock once and call the shared tile owner directly, avoiding nested original-lock acquisition behind a pending relink.

These are additive optional derivative fields/kinds, with no IndexedDB or project-schema migration. Older builds ignore new display kinds and their optional fields; rollback may recompute displays. Derivatives remain outside backups and project revisions. Browser clearing/eviction or the LRU budget can require later recomputation.

Project deletion removes the document/history and its receipts. Original media is conservatively retained, including shared and historical sources; it is not automatically reclaimed. Explicit original garbage collection needs a later consumer-facing retention policy. Artifact disposal removes the owned export file. Model-cache clearing deletes only the namespaced inference cache.

Version-one JSON backup envelopes contain the project, referenced asset metadata, and referenced source transcripts, without media bytes. Retain originals separately. Import validates the complete envelope and restores all records in one transaction, assigning fresh project, asset, and transcript IDs to avoid replacing existing data. Restored metadata is marked missing until relinking succeeds. The restored project starts at revision zero; relink each remapped asset ID to its original file before media-dependent work. Legacy bare project documents can still be imported, but require metadata already present in the same namespace; source kinds, duration bounds, and transcript ownership are checked before the project is stored. Import journals mark successful file publication transactionally with asset metadata, so interrupted relinks cannot be mistaken for complete originals.

Persisted keyframes have stable IDs. When an older version-one document omits those IDs, parsing generates them deterministically from the clip ID, property, and timestamp. Reopening the same document or retrying a command does not generate different identities. Subsequent snapshots and backups include the normalized IDs; no schema-version change or destructive storage migration is required.

Stored project records carry `identityVersion: 1` outside the canonical project document. Reading an unmarked legacy record normalizes its current project and complete undo/redo history in one IndexedDB transaction. The original release's duplicateClip operation could copy caption cue IDs; migration preserves the first owner in chronological history (oldest undo, current, then future redo order) and deterministically remaps later owners by clip ID and old cue ID. Reordering tracks cannot exchange identities across history. Missing legacy keyframe IDs are normalized at the same time. This structural migration does not advance any editing revision or change visual/timing content. Unsupported records, same-clip duplicates, and IDs colliding with other object kinds abort without publishing a marker. Marked records stay strict and do not repeat the history migration on normal reads.

New backup envelopes also carry `identityVersion: 1`. Unmarked external backups and bare documents are strict by default; callers may explicitly opt into the same limited cue repair with `projects.importJSON(text, { repairLegacyIdentities: true })`. The option cannot relax validation for marked backups. Backups include editing data and references, not originals or receipt/history tables.

New receipts carry `contentVersion: 2` and canonical raw request JSON. Unversioned receipts are compared using the exact original version-one parser behavior, rather than today's defaulting or ID generation. Thus an identical successful old request still replays after upgrade and before stale-revision checks, while changed content and newly supplied nested IDs conflict. Receipt contents are never silently rewritten during migration; unknown receipt versions fail closed.

## Workspace and project transfer

The new version-one `localcut-workspace` envelope contains selected current project documents, optional saved versions, referenced source metadata/transcripts, optional whitelisted appearance/workspace settings, and a file manifest. Project transfer uses the same envelope with one project and no settings. Metadata-only exports are JSON. Bundled originals use ZIP entries `workspace.json` and `assets/<index>`; the manifest records source ID, size and SHA-256. Shared and historical sources are deduplicated. Excluding versions prunes sources referenced only by those versions. Current pending edits are included from the committed document, independently of the one-second version debounce.

Imports inspect the complete envelope and ZIP directory before mutation: supported version, strict schemas, unique project/source/transcript/version/file IDs, complete references, source types and bounds, version lineage, safe paths, expanded byte limits, declared files, ZIP CRC-32 and original SHA-256. Selected original bytes are checked again at publication and inspected using the existing native media inspector. ZIP64, encrypted, duplicate/unsafe entries and unknown extra files are rejected. Metadata is limited to 16 MiB; archives/expanded contents to 512 MiB; selected export sources to 496 MiB. Inflation counts actual emitted bytes against the declared length and limits, using bounded compressed chunks and cancellation yields; declared sizes cannot truncate the decoded result. The archive is inspected in memory within these bounds, with chunked ZIP writing. Large libraries should use multiple selective backups; this is not an unbounded streaming archive format.

Selected projects, their version snapshots, asset metadata and transcripts receive fresh project/source/transcript/version IDs. Internal clip/track/cue IDs retain their project-local meaning. All imported snapshots start at revision zero; saved states/order/kinds/timestamps and restore lineage survive, followed by a new initial version for the imported current state. Undo/redo and request receipts are not transferred. Existing records are never overwritten. Sources excluded at export or import stay marked missing for normal relinking; bundled selected originals are ready immediately. Unreferenced origin originals, derivatives, inference caches, credentials, OAuth/connection/sharing consent and chat/proposal state are excluded.

Every staged original has an import journal and held recovery lease. Quota recovery evicts only eligible derivatives and retries once. Cancellation/failure before publication cleans staged originals; if cleanup fails its journal remains for the next explicit engine recovery. One IndexedDB transaction publishes all selected project records, metadata, transcripts and committed journal markers together. A committed import survives late cancellation; journal cleanup afterward is recoverable. Project notifications follow commit.

Settings are applied through their existing owners after project publication. localStorage and IndexedDB have no shared transaction: a settings write failure reports which preferences were not saved and retains imported projects. The dialog clears their selection so retrying settings does not duplicate those copies. Settings-only import never opens editing storage or starts workers/provider requests. Rollback retains regular imported projects and existing legacy backup compatibility; older builds ignore the separate transfer envelope.

No application shell caching or offline navigation is installed. Cached inference can run without remote model/runtime hosts after reload as long as the static app itself remains available.

Storyboard export bytes use the existing journaled derivative cache, keyed by the pinned Excalidraw renderer version, selected scene content and rendering options. Cross-tab derivative locks serialize identical renders; cache reads verify stored bytes. Filename and project revision do not affect rendering identity. Cache eviction/recovery rebuilds on the next explicit export. PNG/SVG/scene artifacts are Blob-backed queued results, independent of derivative disposal; Store PNG imports a separate immutable original and named library entry. No new persisted project field, database store or migration is introduced. Project Undo never removes stored Media assets; library Trash/Restore retains editing originals. Failed named placement after committed import retains the original and reports failure rather than automatically duplicating the store action.

## Timeline metadata compatibility

Version-one clips may now carry optional `groupId`; transitions may carry optional template ID and strength. Existing documents omit these fields and retain their behavior. Membership and generated template keyframes persist through the existing atomic document/history/receipt commits, immutable versions and JSON backups; no database version or new store is needed. Groups use globally distinct IDs, require at least two members, and are validated on open/import. Originals are reused for separated audio.

An older application build with strict schemas rejects these fields in working documents and saved history/version snapshots. Export backups before downgrading. Use a fresh storage namespace and a compatible backup without group/template metadata if an older build is required; ungrouping or restoring only the working state can leave newer snapshots behind. Reverting app files alone is not a compatibility migration. Ordinary generated attribute keyframes remain compatible with the existing renderer.

Speed ramps, pitch mode and nominal `speedRampSourceRange` split bounds are optional version-one clip fields. Split provenance survives history, backup, duplication and audio separation; its endpoints must round to the actual source range. Older documents with omitted pitch mode use change pitch and no ramp; parsing does not inject new fields; current history, immutable versions and workspace/project transfer retain authored settings through the shared project schema. No IndexedDB migration or receipt rewrite is needed. Older app builds reject projects/backups containing these fields, so rollback requires retaining this revision to read newer authored documents.

## Asset index sidecar

Explicit indexing or index inspection opens `${namespace}-asset-index-v1` (IndexedDB version 1), with `runs` and `journal` stores, and `${namespace}/asset-index/` in OPFS. This leaves the existing editor database version, project schema, versions, receipts and JSON backup envelope unchanged. Index transfer is deferred.

Version-one `AssetIndexRun` records retain source size/last-modified identity, oriented dimensions, audio presence, analysis settings and every sampled measurement, scene ranges/scores, generated file references, statuses, labels, safe request manifests, raw returned labeling text, selected/actual model and reported usage. Manifests reference generated file IDs and omit base64 payloads, credentials and transport headers. Previous runs remain retained. Audio runs retain versioned energy/silence settings, RMS/peak windows, segment ranges and WAV excerpts. Images also retain dHash, color histogram and quality metrics for approximate duplicate comparisons.

Each file is journaled before writing and added to its scene in the same transaction that clears its journal. Recovery checks file locks before removing unpublished files; an active run lock protects analysis and labeling across tabs. Abandoned jobs become cancelled, with completed scene artifacts/labels preserved for explicit retry. Deletion marks a run invalid and deleting before removing files; recovery finishes an interrupted explicit deletion. Cancellation/revocation prevents subsequent publication without undoing completed checkpoints.

Generated evidence is outside derivative LRU eviction. Quota errors report `QUOTA_EXCEEDED`; delete a retained run explicitly to free space. History reports run records plus artifact bytes, excluding browser implementation overhead. Relink invalidates prior indexes under the original-file lock. New analysis holds a shared original lock and labeling checks source identity again before committing; concurrent source changes cannot publish valid labels. Browser-origin eviction remains possible, so retain original backups. Disconnecting cancels provider work and retains all local outputs.

## OpenRouter credential record

The workspace stores the versioned `localcut.openrouter-credential.v1` record in origin-local `localStorage`, separately from preferences and editing storage. Both pasted keys and OAuth exchange results persist here. The shared adapter opts in through `credentialStorage`; explicit `restoreCredential()` validates the record without network activity. Disconnect removes only the owned credential and temporary OAuth state; disposal preserves the credential. Denied/full storage and invalid records fail with sanitized errors. Other tabs retire their current connection on credential replacement/removal. Browser data clearing removes the record. Project/workspace backups exclude it, and older code ignores it. See [saved connection behavior](ai.md#saved-workspace-connection).

## Durable task sidecar

Explicit editing or granted screen capture opens `${namespace}-tasks-v1`, IndexedDB version 1, with `tasks`, `inputs` and `results` stores. This additive sidecar leaves project/history/receipt formats unchanged. Tasks retain versioned status, immutable submitted input and structured-cloneable results such as speech samples, audio files, exports and archive files. Native handles, object URLs, closures, credentials and provider error bodies are excluded. Task data is origin-local and excluded from portable workspace/project backups.

Inputs commit before dispatch. A per-lane Web Lock serializes work across tabs; an owner lock protects queued session callbacks, and a per-task lock distinguishes an active owner from an abandoned running record. Safe local work returns to queued; uncertain or non-idempotent work becomes interrupted with an explicit retry action. A submitted speech take checkpoints its source samples before local timing, so a local rendering retry can reuse the same take. Completing a task atomically checks cancellation and publishes its result and completed status. Cancellation aborts pending disposable-result publication; a committed canonical import/transcript remains successful. Cancellation cannot undo an already committed import/transcript. Queue metadata/result publication is a separate transaction from canonical project commits: if saving task results fails, inspect the project before retrying a publication.

Reusable task records add optional `cacheKey`/`cacheVersion` fields to this version-one sidecar, without a schema migration. Admission has three layers: validated domain artifacts, a bounded 128-entry queue-key lookup, and persisted task claims/results. Keys hash task kind, policy version, source/content identity and result-affecting parameters; they never grant sharing or provider authority. A cache hit creates no queue record or global task event. Under a namespaced cache-admission Web Lock, misses recheck the domain cache, join a matching queued/running/retrying task, reuse an eligible completed pure result, or commit the new key/inputs/task before dispatch. Failed, cancelled, interrupted, removed or missing-result records do not qualify. Pending claims from another algorithm version become interrupted and require a new request; they cannot execute or retry with the current handler. Result publication remains atomic with terminal success.

Media and model-preparation policies reuse in-flight work but validate their owner cache on every request. They never reuse completed queue artifacts after a domain miss, preventing relink/eviction/corruption from resurrecting obsolete results. Pure local PCM measurement and speech timing permit completed-result reuse, returning a structured clone to each consumer. Fresh policies cover import/relink, explicit analysis/index runs, canonical transcript publication, remote inference, native preflight, exports/transfers, assistant work, speech-provider generation, dictation and capture. These actions retain their current commit, consent, disposable-resource and checkpoint contracts. Legacy records without keys and external handlers without policies remain fresh.

Cancelling a reusable consumer Job detaches its wait while shared work continues. Explicit `tasks.cancel(taskId)` cancels the durable task and all remaining consumers. Cache hits and joined consumers have independent Job IDs; only a new miss uses its Job ID for the durable task. Engine disposal retires its owner and eligible interrupted local work can recover in another queue.

The queue retains inputs/results until the user removes their task. Removing a record deletes its owned queue data and disposes retained export artifacts; it does not delete imported originals, project edits or transcription/index outputs. Browser quota/eviction still applies. Reverting the feature leaves this sidecar unused; older builds can continue reading existing projects. Closing the application stops local processing; reopening an explicit project resumes eligible queued work, while interrupted provider submissions require review/retry.

Chat export tasks (`chat.export.v1`) use this sidecar for a version-one allowlisted point-in-time transcript input and a ZIP File result. A fresh-task policy gives each explicit click its own export timestamp/snapshot; downloads reuse that task's retained result. The editor registers the handler before queue startup, so queued and abandoned running tasks rebuild only the captured input independently of the chat UI/provider. Inputs include permitted visible text/tool/proposal records, draft and local attachment metadata; no source files or executable assistant checkpoint. No project or IndexedDB migration is needed.

## Voice presets

`localcut.voice-presets.v1` is a versioned origin-local localStorage record, capped at 100 presets. Each stable ID owns a bounded name, model, voice, languages, delivery instructions and archived flag. The owner validates and whitelists fields, patches the latest stored list and publishes only after a successful write; denied/full storage reports a save error. Storage events synchronize open dialogs across tabs. A reference preset also owns a bounded `referenceId`; legacy settings-only records remain readable. Audio bytes, the matching reference script and optional measured phrase timing live in the lazy origin-local `localcut-voice-references-v1` IndexedDB sidecar, version 1, `references` store. Save writes an original, unretimed generated WAV and transcript before publishing preset metadata; failed metadata publication removes the new reference. Queue-result deletion does not remove favorites. Archive preserves both settings and reference and is reversible. Presets/references exclude credentials, retiming settings, object URLs and sharing consent, remain independent of project data, and are not included in portable project/workspace backups. Generate snapshots WAV base64/transcript into its durable task input, so rename/archive cannot alter a submitted request.

## Local project organization

Project records have an optional additive `catalog` field containing an independent revision, archive flag, custom thumbnail Blob and framing position. Updates are atomic revision-checked IndexedDB transactions. Edits, undo/redo and version restoration preserve this field. No database-version or project-schema migration is needed. Archiving never deletes documents, versions, receipts or originals; archived projects can still be opened, restored and exported.

Custom covers are decoded/resized locally to at most 1,280 pixels on the longest edge. Source files and object URLs are never stored in project JSON. The display cache excludes image bytes, source references and mutation revisions. Catalog organization is excluded from portable editing backups; imported copies start active with automatic previews. Older writers may discard this additive field, so retain an origin-storage backup before rollback when organization must survive.

Generated speech transcripts add optional `speech` metadata to the existing strict transcript schema. Script, TTS identity/directions/languages, original duration, measured rendered-source cues and padding stay local with the asset transcript. Padded editing cues must not overlap; measured cues remain ordered and within the asset. Import/backup validation enforces these boundaries. Existing transcripts without metadata remain readable without an IndexedDB upgrade. Older strict readers cannot read the new metadata; retain this build or export rendered media before rolling back. Queue checkpoints retain audio and measured phrases independently of dialog lifetime; favorite references retain original timing independently of queue deletion.

## Project storyboard

The optional additive `storyboard` field in schema-version-one projects contains validated vector/text Excalidraw elements and a canvas background color. Older documents without it remain valid and open with an empty storyboard. Canvas selection, pan/zoom, active tools, collaborators and file handles are session state; they are not project data. Fonts are pinned deployment assets, not user data. The storyboard uses existing atomic project/history/receipt commits and version snapshots, without a sidecar database or destructive migration.

Project JSON and workspace backups preserve current and historical storyboards when those snapshots are selected. Scene element IDs are scoped to their project diagram and remain stable when a backup becomes a new project copy. Imports still remap project/media identities through their existing owner. Browser agents read `projects.snapshot` and apply the same revision-aware commands. A stale canvas write fails and refreshes authoritative content instead of overwriting another writer; the user can retry the drawing.

Downgrade compatibility: old strict readers do not recognize the `storyboard` field in populated project documents or backups. Preserve a current-format backup and use a compatible release to reopen it; reverting application code is not a data migration. No automatic removal of storyboards is performed.

## Notification diagnostics

Notification history uses the display-only `localcut.notifications.v1` localStorage record independently of editor storage. The version-one record contains whitelisted notification IDs/types/messages/descriptions/timestamps/read flags and optional original error-report text. It retains 500 recent entries within a 4 MiB UTF-8 envelope; eviction removes whole oldest reports. Denied/full storage or unavailable browser write locks leave the complete session report available and exposes Retry saving. Clear history affects only this record. Storage events synchronize open tabs; each write holds a shared browser Web Lock around the complete read/modify/write against the latest saved record. History is excluded from portable project/workspace backups and never hydrates an editing session.

Durable task failures have an optional diagnostic field holding safe stack/cause/aggregate data. Existing task records without diagnostics remain readable and report missing stacks explicitly. Untrusted message headers/provider bodies are omitted; HTTP status and the known `output_limit` reason are retained. No IndexedDB migration or task lifecycle/retry changes are introduced.

## Capture metadata persistence

Optional validated `Asset.capture` lives beside technical asset metadata in the existing IndexedDB `assets` store; original bytes remain in OPFS. Project JSON and workspace archives preserve it through the canonical asset schema and ID remapping, including omitted-original backups. No database version migration or startup reparse is needed. `AssetIndexRun.source.capture` snapshots those facts during local analysis without recomputing them after refresh; relink invalidates old runs through the existing source lifecycle. Metadata limits/format support are in [the API contract](api.md#embedded-asset-capture-metadata). A request manifest records `captureIncluded`; its publication sets the run's sticky `captureShared` flag before provider traffic, covering failed/retried work as well as successful labels. These retained source facts never become disposable derivatives.

## Local chat sessions

Usage may include additive `cachedTokens`, `cacheWriteTokens` and `reasoningTokens` counters alongside total tokens/cost. Older records omit them; restoration and forks preserve them when present without a version/database migration. Saved chat UUIDs also identify related OpenRouter requests after explicit Send; restoring a record alone never submits inference. See [request management](ai.md#request-management-and-documentation-audit).

The additive `localcut-chats-v1` IndexedDB sidecar owns version-one display records, separate from project JSON, credentials, workspace preferences, portable backups and derivative eviction. `sessions` uses `[scope, id]` keys and a scope index; `selection` remembers the selected UUID in each context. Its prefix contains project identity, configured LLM endpoints/routes/provider identities and model, excluding credential generations. Connected OpenRouter contexts append `openrouter-context-v1`; other scopes keep their original text/name/transcript flags and optional capture marker. Reading requires an opened project and configured model. Restoration never starts inference.

When an explicitly OpenRouter-authorized scope loads, one read/write transaction migrates all 48 matching prior sharing/indexing variants into it, preserving IDs, drafts, messages, manual titles and archive state. Canonical records win duplicate IDs. A valid canonical active selection wins; otherwise the first valid legacy active selection is reused. Project/model/provider prefixes must match exactly. Other scopes continue to migrate only the obsolete indexing bit, retaining privacy boundaries. Migrated records and selections move atomically, and repeated reloads do not duplicate sessions. An older app can write a legacy scope again; the next load migrates it. Migration changes sidecar keys, so reverting code can hide migrated chats; prefer a forward fix preserving the authorized scope reader. Project data remains compatible.

Records whitelist titles and additive `titleLocked`/`archived` flags (defaulting to false for older version-one records), user/assistant text, usage and historical tool activity, composer text and local image asset IDs. Writes patch changed sessions and selection transactionally; another tab's unrelated session is retained. The same session uses last-committed-write semantics. Missing or invalid records are ignored safely; unknown versions cannot hydrate authority. Streaming/paused replies and unfinished tools restore as stopped historical activity. Attachment IDs are revalidated against ready local images. Completed text-only turns and canonical interrupted continuation text can seed the assistant's retained history after explicit Send; protocol tools, executable proposals, approvals, loaded skills, credentials and sharing consent are never restored. Interrupted messages may add `continuation: { user, assistant, indexScope? }`, published by the assistant after preserving completed receipts and retiring obsolete observations. It is separate from historical display text/tool rows and consumed only with matching saved index provenance. Legacy or mismatched interruptions recover the user request without unverified narration or tool observations. This is additive version-one metadata; no database migration is needed. The retained history IDs and index-run marker preserve caller-requested retention and stale-index retirement across reloads. Revoking sharing selects a separate context before the next request.

Quota/access failures retain the latest dirty snapshots in memory across scope switches and display an unsaved notice with Retry saving. Retry saves every retained dirty scope; successful saves in one scope cannot erase failures in another. Reselecting the same effective model preserves scope identity even when a redundant saved route model is filled in. Browser eviction/site-data clearing can remove chats; portable project backups do not contain them. Reverting the application leaves the sidecar inert without changing original project compatibility.

Archiving retains a record, with active selection repaired after hydration. Forks receive new UUIDs and a cloned display snapshot with stopped unfinished work and retained history provenance; they never copy live assistant checkpoints. Renames lock automatic title replacement.

## Creative effect state and tracking cache

Clip JSON owns LUT numeric tables, preset strength, blend mode, mask geometry/motion points, chroma key, EQ, balance and spectral suppression settings. Optional fields leave old documents neutral; null clears replacement objects. History and portable project/workspace backups retain them with the clip. Imported LUT titles/file names are not retained. Older releases with strict schemas may reject these new fields; retain the current release and backup when reverting.

The existing durable task result cache retains `media.trackMask` translation results under `mask-translation-v2`. Keys include the captured project/revision, clip, optional draft mask and current source identity. Fresh facade instances can reuse completed results; source relink/revision/settings changes invalidate admission. Results contain only bounded numeric motion/confidence, no frames or originals. The ordinary queue/store eviction and recovery rules apply. Applying a result remains an explicit revision-bound command.

## Media folder library

Explicit library use creates `${namespace}/project-media/${projectId}/media-library/` and `${namespace}/project-media/${projectId}/media-trash/` as actual OPFS directories. Named files and nested folders live beneath these roots. The `${namespace}-media-library-${projectId}-v1` IndexedDB sidecar owns a version-one snapshot with a monotonic revision and stable entries (`id`, `parentId`, `kind`, `name`, optional `assetId`, Trash/previous-parent information and source signature), plus a single active mutation journal. Organization, revisions, mutation locks and change subscriptions are isolated by stable project ID. Renaming a project does not change its filesystem root. Deleting a project retains its root, consistent with original-source retention, but further library access requires an existing project.

The existing immutable originals remain in the editing vault by asset ID. The named library is an additional local copy, streamed with quota reservation and the existing derivative-only eviction/retry policy. Folder moves/renames temporarily require space for a second copy; insufficient quota leaves the source and published organization intact. Original identities, source caches, project revisions, Undo and saved versions are unchanged. Relinking updates every named copy from the new source signature. Ready originals referenced by this project’s current edits, undo/redo or saved versions are adopted on explicit library listing; missing originals keep their relinking path and do not block opening edits. No model or remote work is initiated.

A project-scoped namespace Web Lock serializes that library’s reads/mutations. The journal precedes file mutation; complete copies precede an atomic snapshot/journal publication transaction. Before publication, recovery removes the partial destination; after publication, recovery completes source cleanup. Source refresh uses atomic writable-file replacement and retains the prior file on failed writing. A stale expected library revision rejects before mutation. Imports and copies allocate collision suffixes; explicit conflicting rename/move fails without overwriting. Names cannot contain traversal, separators or control characters, and folders cannot move into themselves or descendants.

Delete moves an entry/subtree to Trash, preserving its stable IDs. Restore returns to its former live parent or root and resolves name collisions. There is no permanent purge or timeline Undo for organization; use Restore for deletion. Library filename changes are separate from the retained source's display metadata. Copy creates new entry IDs referencing the same immutable source asset, so timeline rendering and source caches remain shared.

Existing project/workspace backups retain their selected immutable originals and project/version contracts; library folder organization and Trash are not part of those archive formats. An explicit library folder Download creates a ZIP retaining hierarchy and empty folders. Browser data clearing/eviction can remove both roots and the sidecar. Old application versions ignore these additive resources and retain access to the editing vault.

### Shared-library migration

The released `${namespace}/media-library/`, `${namespace}/media-trash/` and `${namespace}-media-library-v1` sidecar remain preserved for rollback. First project-library access acquires the legacy mutation lock, recovers its journal and freezes ownership for all existing projects in the sidecar’s `state/project-ownership` key. A referenced asset migrates into each owning project, with ancestor folders and previous Trash restore parents. References include current edits, undo/redo and saved versions. Unreferenced entries and empty folders go to the lexicographically first existing project ID so they remain accessible; projects created after that snapshot receive none of this legacy organization.

Each project streams its own named copies, retaining IDs/names and journal-publishing each entry before setting `state/legacy-migrated`. Failed/interrupted copies can resume without removing legacy files or already committed entries. Migration requires additional local storage; quota failure leaves legacy data intact and permits retry. Older app releases continue using the preserved legacy root; their later changes are not synchronized into the frozen migration. If an old tab moves a frozen source path, migration recovers the named copy from its retained immutable editing original, keeping the frozen destination hierarchy. Original editing sources remain in the shared immutable vault. Project/workspace restores create new IDs and independent roots, seeded only from their restored document references; the existing backup formats still omit folder organization and Trash.
