# Optional AI integration

- Own provider adapters, service routing, authentication, context policy, stream parsers, and assistant. Keep imports and construction inert; consumers initiate connection and requests.
- Keep runtime keys private. The workspace opts into a separate persistent credential record; headless clients remain memory-only unless supplied credential storage. Restore is explicit and network-free; Disconnect deletes the record, while disposal preserves it. Only expiring PKCE state/verifier data belongs in tab-scoped OAuth storage; callback secrets and provider error bodies must not leak through logs or public errors.
- Credential replacement, disconnect, and disposal invalidate old generations and abort their work. Late responses cannot restore credentials or publish proposals for a retired session.
- Require an explicit tool-capable model. Allow only one OpenRouter connection and one selection per LLM/TTS/STT service; never fail over after a service error. Local Whisper remains the default STT selection. Indexing retains no automatic model/provider fallback. Capture the project's identity, revision, selected asset allowlist, and context policy for each assistant session.
- Headless names, overlay/caption text, transcripts and capture metadata retain separate caller-controlled opt-ins; the workspace derives all four from the connected OpenRouter account under its disclosed connection terms. Build remote context through `context.ts`; never expand the allowlist or send raw media through chat. The workspace authorizes indexing through OpenRouter connection; headless hosts retain live consent callbacks. The indexer sends generated local stills, audio excerpts and video excerpts with sound; preserve dedicated selected-model validation, safe manifests and explicit retries.
- Treat provider text and tool arguments as untrusted. Apply the no-cap chat preference in [user preferences](../../docs/user-preferences.md#assistant-caps--12-october-2026): no default/hard request, response, round, tool, history, proposal or duration ceilings. Respect only explicitly supplied caller budgets and provider/editor data contracts; require complete terminal/type/schema validation before exposing executable tool calls.
- Keep complete capability discovery independent of execution permission: all fixed domain guidance is loadable, and `tools.ts` owns the typed rules shared by tool/action declarations, per-round `capabilityMap` and safe rejected-call recovery. Update that registry and the cross-domain discovery/recovery regressions when adding any tool or action. A filtered declaration must never be treated as the complete feature inventory.
- Keep runtime prompt ownership and failure/resume guidance aligned with [prompt and skill maintenance](../../docs/ai.md#prompt-and-skill-maintenance). Put facts in the shared capability/context owners and conditional workflows in their lazy skill; prove changed guidance with behavior and recovery regressions, not only string-presence assertions.
- Keep the initial tool surface to skill loading and core inspection. The fixed catalog in `skills.ts` owns discovery; dynamically import domain guidance from `skills/` only after an explicit `load_skill`. Recompute tool/action schemas each round, enforce the frozen round authority at execution, and reset loads per turn. Skill loading never grants approval, service capability or context-sharing consent.
- Follow the [feature-access maintenance contract](../../docs/development.md#keep-agent-access-complete); [AI inventory](../../docs/ai.md#editing-feature-access-inventory) maps the editing surface. Discover properties/operations from canonical schemas and fonts/templates from the shared catalogs.
- The workspace host selects `execution: requested` as specified in [the execution contract](../../docs/ai.md#workspace-requested-execution); infer authorization from user requests, ask only missing-information text questions, choose independent sibling calls or dependent later rounds, execute through the shared proposal executor and exhaustive tool scheduling policy, and return authoritative receipts before continuing. Keep project/scope changes as barriers; distinct indexing assets and read-only tools may overlap, while repeated assets serialize. Drain active siblings on cancellation and refresh shared context at batch boundaries. Failed paid tool/service actions cannot retry in the same turn. The assistant round owner silently retries transient chat inference before visible output using the same frozen request; never replay completed tools, override refusals or widen context. Default headless tools inspect and propose. `applyProposal` retains the edit-only contract; explicit `approveProposal` can also execute reviewed history/export/transcription/indexing/preparation actions. Preserve request IDs, stale-revision rejection and committed results during disposal. Never expose a model approval/policy-switch tool, prepare a model outside requested work or trigger a browser Save.
- Keep conversation history, supplied context snapshots and tool replies immutable under [the continuity preference](../../docs/user-preferences.md#immutable-chat-continuity--13-october-2026). Recompute fresh context every turn; never retire old messages because index runs or asset scope changed. Retain skill results verbatim while resetting current skill authority. Persist canonical exchanges through the chat sidecar; restoration never executes historical tools.

- Every submitted turn updates the persistent session goal before execution, reconciles task notes in a separate tool-free agent after each iteration and joins that update at the next boundary. The shared auxiliary owner selects a stage-specific internal document role and final task together, and ends quoted evidence with that exact task; prior assistant replies, tool instructions and malformed task notes cannot redefine those roles. Goals, to-dos and completion assessments are verbatim text: format advice belongs in prompts, never host parsers, checkbox gates, verdict markers or format-specific repair. The main agent consumes completion feedback and chooses further tools or a final answer; three review checks and caller budgets retain their stopping boundaries. Preserve context-change invalidation through separate host metadata without rewriting the assessment. Review is advisory data, never action authority. Retain cancellation/refusal, consent, user-owned actions, failed paid-action retry guards and auxiliary usage accounting. See the [completion review contract](../../docs/ai.md#request-completion-review).

- Auxiliary text streams through display-only `review_progress` events keyed by turn/call/stage. Reset failed attempts and keep drafts out of canonical history/session goals; terminal validation and existing completion/authority rules remain the acceptance boundary. Cancellation and retirement suppress late progress; never display opaque provider reasoning. See [chat streaming checks](../../docs/development.md#chat-streaming-progress-checks).

- HTTP/SSE diagnostics retain only allowlisted machine categories/parameter names and the local inference stage (goal definition, to-do update, main response or completion check). HTTP diagnostic reads have their own bounded size/time budget; unknown, oversized or unreadable bodies retain the original status. Never forward remote messages/raw metadata or infer a specific rejection from HTTP 400 alone. `errors.ts` owns safe classification, `protocol.ts` owns bounded reads and `conversation-errors.ts` owns recovery copy.
- Model/privacy changes require a new session. Cancellation discards unfinished proposals without allowing late work to republish them. Forward only approved progress and result metadata; retain export Files locally and dispose them with their owner. Transcription proposals disclose the frozen local/remote STT route from trusted configuration; a model cannot alter recipients. Approval may send the selected audio to the selected OpenRouter STT model but never grants remote transcript-text sharing.

- Speech discovery/requests reuse this adapter's in-memory credentials, cancellation generation and fixed endpoints. Offer Gemini models with advertised voices and the documented PCM contract, the documented ElevenLabs models with validated typed options under `provider.options.elevenlabs`, plus Fish Audio S2.1 Pro only when its endpoint advertises voice cloning. Reference synthesis accepts an explicitly selected saved generated WAV and matching transcript, returns MP3 and normalizes decoded audio to the existing 24 kHz mono contract. Never send project source media/context or upload a reference to another service. `speech-audio.ts` owns local pitch-preserving timing and WAV rendering; controls do not duplicate that processing. Generated-audio timing delegates to the shared transcription facade using the configured STT route; local Whisper requires explicit preparation. The speech dialog has no separate timing route selection or informational section. Remote STT normalization belongs to `transcription.ts`: sort usable measured segments, omit empty/instantaneous entries and clip trailing ends to audio; reject malformed ranges without fabricating times. The ElevenLabs capability/validation owner is `elevenlabs.ts`; reject unsupported options before network submission, keep native rate distinct from local timing, and retain options in user presets and immutable queue inputs. Hide unsupported speech controls rather than disabling them; Fish reference synthesis omits stock voice, languages and delivery, while local timing remains available. Retain measured phrase provenance and nonoverlapping padded editing cues; read_transcript keeps its separate sharing gate. The explicitly submitted speech queue retries rejected rate-limit requests within its bounded budget; ambiguous submissions require explicit retry.

Creative catalogs/schemas remain in `inspect_capabilities.properties.effects`, derived from `core/effects.ts`. `track_mask` is an editing-domain action with independent host-support/loading rules; it requires a saved video mask and commits at its captured revision through the current host execution policy (default headless review or requested workspace execution). Keep the exhaustive action matrix and real persisted tracking journey current. LUT file selection stays user-owned; never invent an imported table. See [creative effect checks](../../docs/development.md#creative-effect-checks).

Storyboard export/store actions use independently discovered `editor.storyboard` capabilities and the lazy storyboard skill. Generated Media IDs extend only the creating assistant session's asset scope. Keep local export bytes out of provider/tool metadata; retain default headless review, requested workspace execution and user Save. Maintain the [workflow recipes](../../docs/storyboard-workflows.md), canonical storyboard schemas and export/asset/revision regressions together.

Library inspection and resolution live in `library-context.ts`, using only `editor.library.forProject(projectId)` registered entries. Preserve registered versus authorized counts/completeness, recursive/shallow pagination and inherited Trash exclusion. `resolve_library_assets` is discoverable through editing or indexing and returns a revision-bound manifest before any service work. Workspace `libraryAccess: project` is a trusted host policy on explicit Send; headless defaults retain the caller allowlist. Scope lasts for the current turn, with dependent proposals freezing/rechecking the library revision; it never grants sharing, raw files, another project or service consent. Stale scope must not block independent authoring. Keep source-dependent storyboard guidance honest about missing evidence and provisional creative work. Use [chat library resolution checks](../../docs/development.md#chat-library-resolution-checks).

`insert_storyboard_image` uses `editor.storyboard.insertImage` for authorized source images/video stills, with project/library revision checks and metadata-only receipts. Canonical image geometry stays in the shared storyboard schema. Pixels hydrate locally for the canvas and exports; never include BinaryFiles in remote context.

- Leave unspecified chat output budgets to provider admission. The catalog maximum is not the remaining context budget after the prompt; never inject it as `max_tokens`. Preserve explicit caller limits and full historical reasoning/tool replies. Terminal response diagnostics use the core safe failure snapshot and remain local display data through chat reload/export.

- Read-only auxiliary responses use ordinary tool-free transport validation. Reject actual tool calls, but do not inspect response text for serialized tool tokens or required formatting. Keep control-delimiter escaping lossless in supplied evidence and leave saved text unchanged. Cover arbitrary prose/Markdown, literal markup, main-agent decisions, caller budgets, cancellation, current-state review and receipt preservation in the goal-review/assistant suites and production completion journey.
