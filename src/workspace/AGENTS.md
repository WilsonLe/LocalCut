# Workspace

- Use task-facing copy: names, content, ranges, labels, actions and actionable failures. Do not add storage/implementation explanations or workflow narration to dialogs, forms, previews or empty states. Explanations belong in documentation unless they change a concrete user decision. See the [source-clip and copy preference](../../docs/user-preferences.md#source-clips-and-task-facing-copy--12-november-2026).

- `useWebMCP.ts` binds optional vendor-neutral [site tools](../../docs/webmcp.md) to the viewed project/version. Keep registration lazy, route identity checked at invocation, canonical schemas/receipts intact and owned jobs/artifacts disposable. This external transport does not restore a built-in assistant or require a provider connection.
- `useWorkspaceWebMCP.ts` exposes setup/status before a project opens. Registration/status must not initialize editing services. Reuse the shell's lazy editor, navigation and file input; preserve a file selection's originating URL/project until selection finishes, then use the ordinary media importer.
- `webmcp/connection.ts` owns shared registration/status and manual refresh. Keep registration signals separate from service/job lifetimes; see [connection status and refresh](../../docs/webmcp.md#connection-status-and-refresh).

- Render cached catalog summaries while revalidating; opening always reads an authoritative engine snapshot. Keep cold skeletons regional, theme-aware and reduced-motion safe. The lightweight shell/catalog may load eagerly within the bundle budget; engine and heavy panels retain their lazy boundaries.
- Use the router and focused workspace hooks for route identity, current snapshot, navigation loading and saved-project catalog state. Derive the active screen from the URL; abort superseded loads before publishing. Preserve pending/error recovery, inert fresh startup and recent-project restoration at initial bare startup, and both hash-route hosting bases.
- Own view state and interaction in this directory; the editor snapshot is the canonical saved project. Route edits, history, imports, preview, and export through the public editor API.
- `useTimelineEditing.ts` owns gesture-to-command wiring and the session clipboard, calling the shell's revision-aware mutation/error owners. `useWorkspaceLayout.ts` owns responsive panel state and focus recovery through the existing preference store. Keep lifecycle/navigation in `Workspace.tsx`; follow [coding rules](../../CONTRIBUTING.md#coding-rules) rather than adding another project state or service implementation.
- `media-import.ts` coordinates explicit imports through engine jobs and serializes folder placements against the initiating project. `useMediaImport.ts` owns batch display/dismissal and the shared placement ref across renders. Create/invoke the coordinator only from event callbacks; preserve live unmount/navigation guards, full-selection enqueue, late committed originals and subscription cleanup. File inputs, app/Media drops and recording reuse this path; dismissal never cancels engine jobs.
- Submit property edits against the revision that authored the form. On conflict, refresh and let the user retry; never silently apply stale values to a newer snapshot.
- Preserve exact source endpoints for gain-only and speed-only changes. An explicit duration edit may change the source range; avoid round trips through displayed seconds for untouched values.
- Keep editor imports lazy behind explicit actions and the project-route/recent-project startup exceptions recorded in the parent guide.

- Keep `WorkspaceDialogs` and optional panels on demand. Dialog consumers use `on-demand-dialog.tsx`: immediate cancellable opening feedback, a semantic loading shell once its optional primitives arrive, then ordinary store publication of the loaded component. Do not put first-open dialogs or their selects behind a blank Suspense retry. Preserve the opener for each closed-to-open transition, including retained dialogs, through loading and dismissal; never reopen after a cancelled load. Command metadata and palette code load concurrently on the explicit opening action; show command controls only after both are ready. Text and clip-properties bodies remain separate optional imports. Measure the full initial import graph with `pnpm check:bundle`; moving JSX alone may leave an eager dependency elsewhere.
- Keep progress, cancellation, errors, and saved revisions tied to actual jobs and receipts. Ignore superseded async results; tear down subscriptions, sessions, and artifacts with their owner.
- Keep the last successfully opened project identity in `recent-project.ts`, outside preferences/backups; only the Workspace shell opts into consuming it on initial bare navigation; other route-hook consumers must remain passive and preserve explicit routes. Keep local editing preferences whitelisted and discard removed agent fields on legacy backup import. Save deliberate layout changes, not responsive measurements or automatic panel opening.
- Keep less frequent controls in the grouped settings menu. Follow the recorded [workspace preferences](../../docs/user-preferences.md) and [behavior](../../docs/workspace.md).
- Appearance shares the text-editor font catalog through its lazy font picker/adapter. Reuse the checksum-verified media loader for selected faces, prepare all subsets for future UI text, and keep pending/error/retry and stale-load guards in the appearance owner. Default startup must not load the catalog/fonts; saved bundled selections may load those display assets without editing services. Portable settings validate the complete catalog.
- Keep keyboard edits in the shared shortcut resolver. Single-key commands apply only inside the focused editor; never steal typing, IME composition, native button activation or modal/menu keys. Route playback through its existing session owner and editing shortcuts through the same revision-aware commands as visible controls.

Use the cached production UI runner for the affected scenario; for timing/revision properties:

```sh
pnpm test:ui --grep 'stale property|speed rounding'
```

For scrolling or settings changes, select the matching title in `tests/browser/workspace-regressions.spec.ts` or `workspace-local-preferences.spec.ts` (which includes the settings journey). Follow the [development loop](../../docs/development.md) for build freshness and broader gates.

- Route notifications through `notifications.ts` and errors through `showErrorToast` in `error-toast.tsx`; pass the original caught error instead of reducing it to a message. This preserves stack/session diagnostics and the persistent bell history. Keep reports local and preserve source error messages/stacks without a hardcoded safe-message allowlist; redact credentials/callback parameters. Do not read extra provider bodies, project/user content or credential stores, or initialize editor services to collect diagnostics. Use the focused notification recipe in [development](../../docs/development.md#notification-history-checks).

- `MediaFolders.tsx` owns folder navigation/forms and calls `editor.library`; freeze the library revision when opening a form. Folder upload/drop hierarchy flows through `folder-upload.ts` and the shared placement API. Preserve thumbnail-to-timeline dragging and offer context-menu move alternatives. See [Media folders](../../docs/workspace.md#media-folders).
